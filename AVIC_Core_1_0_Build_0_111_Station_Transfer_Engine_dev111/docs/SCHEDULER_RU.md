# Scheduler Manager — спецификация и реализация DEV47

## Назначение
Scheduler хранит типизированное расписание станции, вычисляет ожидаемое значение по локальному времени и сообщает источник решения. Он не является драйвером и не должен самостоятельно отправлять физические команды.

## Объект расписания
- `id`, `station_id`, `name`;
- `value_type`: BOOLEAN / NUMERIC / ENUM / STRING;
- `timezone`: IANA time zone;
- `default_value`;
- `effective_start`, `effective_end`, `enabled`;
- `revision` для optimistic concurrency;
- weekly events, special events, point bindings.

## Недельные события
Каждое событие содержит день недели (0=понедельник … 6=воскресенье), `start_minute`, `end_minute` и значение. Интервал полуоткрытый: начало включено, конец не включён. Конец должен быть позже начала. Интервал через полночь задаётся двумя событиями. Пересекающиеся интервалы одного дня запрещены.

## Календарные исключения
Исключение имеет название, даты начала/окончания включительно, локальный временной интервал, значение и приоритет 1–16. Пересечение исключений одинакового приоритета запрещено. Исключения с разными приоритетами могут пересекаться; выигрывает наибольший приоритет. При равном приоритете конфликт предотвращается на этапе записи.

## Приоритет вычисления DEV47
1. MANUAL_OVERRIDE — временное ручное переопределение с оператором, причиной и временем окончания.
2. SPECIAL_EVENT — календарное исключение с наибольшим приоритетом.
3. WEEKLY_SCHEDULE — событие недельного расписания.
4. DEFAULT — значение по умолчанию.

Эта цепочка описывает только приоритеты Scheduler. Она не заменяет будущий арбитраж всех источников управления (оператор, внешняя команда, interlock, аварийная защита, расписание и локальный контроллер). Такое разрешение должно быть централизовано в Command Manager.

## Привязка точек
Разрешены только точки OUTPUT/INOUT, принадлежащие той же станции, с совместимым типом. Привязка не означает разрешение физической записи. DEV47 сохраняет список назначений и возвращает их в evaluation result.

## API
- `GET /api/stations/{station_id}/schedules`
- `POST /api/schedules`
- `POST /api/schedules/{id}/weekly-events`
- `DELETE /api/schedules/{id}/weekly-events/{event_id}`
- `POST /api/schedules/{id}/special-events`
- `DELETE /api/schedules/{id}/special-events/{event_id}`
- `GET /api/schedules/{id}/evaluate`
- `GET /api/stations/{station_id}/schedule-points?value_type=BOOLEAN`
- `POST|DELETE /api/schedules/{id}/points/{point_id}`
- `POST|DELETE /api/schedules/{id}/override`

## Результат evaluate
Возвращаются value, value_type, source, source_id, evaluated_at, local_time, timezone, next_change (время, значение и источник следующего переключения), point_ids и `output_mode=INTENT_ONLY_NO_FIELD_WRITE`.

## Следующий этап
- 24-часовая недельная сетка с drag/resize, копированием дней и M-F.
- Calendar Manager: annual/recurring rules, календарные объекты, многодневные события и исключения по типу.
- Schedule Selector и Trigger Schedule.
- Scheduler Runtime с контролируемой периодической оценкой, восстановлением после перезапуска и журналом исполнения.
- Command Manager: разрешение конфликтов, ручной override с истечением, external priority, interlocks, approval, read-back и безопасная публикация.

## DEV48 — недельная сетка и массовое копирование

В DEV48 добавлена обзорная 24-часовая сетка на семь дней. Блок события показывает время начала, значение и длительность; подробный список остаётся доступен для точной проверки и удаления.

Операция `POST /api/schedules/{schedule_id}/weekly-days/copy` принимает `source_day`, `target_days` и `expected_revision`. Дни недели нумеруются от 0 (понедельник) до 6 (воскресенье). Содержимое целевых дней заменяется копией исходного дня в одной транзакции. Исходный день не изменяется. Пустой исходный день очищает целевые дни. Дубли дней, неверные номера и включение исходного дня в назначения отклоняются. При устаревшей ревизии возвращается конфликт.

В интерфейсе доступны «Применить Пн–Пт» и «Копировать на остальные дни». Выбранный день служит источником. Копирование не меняет точки и не отправляет команды оборудованию.

Ограничение: сетка DEV48 пока обзорная, без drag/resize. Редактирование событий выполняется через поля ввода и список.
