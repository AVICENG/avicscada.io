# DEV121 — управляемый цикл опроса драйверов

## Назначение

BACnet/IP и Modbus TCP имели одноразовый `poll_once()`: инженер мог проверить отдельный опрос, но не существовало общего владельца периодического расписания и остановки. DEV121 добавляет `PollingSession` — один поток на экземпляр адаптера, без параллельных опросов одного экземпляра.

## Поведение

- Явный `start()` / `stop()`; повторный start идемпотентен.
- Первый опрос начинается сразу после старта.
- Интервал задаётся явно (0,1–86400 секунд).
- Один worker; следующий опрос не стартует, пока предыдущий не завершён.
- Нет догоняющих параллельных опросов при задержках.
- Диагностика: состояние, число циклов, успехи/ошибки точек, время последнего запуска/завершения, последняя ошибка.
- Per-point quality остаётся ответственностью адаптера: потеря связи сохраняет последнее значение и меняет качество.
- Исключение в одном цикле не убивает worker; сессия становится DEGRADED и продолжает следующий цикл.
- stop(timeout) сигнализирует завершение и ждёт worker; по превышении timeout возвращает TimeoutError, не притворяясь, что поток остановлен.

## Границы

PollingSession — общий синхронный supervisor, не полноценный Driver Manager lifecycle. Нет планирования по календарю, jitter, rate grouping, connection pooling, COV, watchdog процесса или распределённого scheduler. Для MQTT push-модель не используется. BACnet/Modbus всё ещё требуют испытаний с физическими устройствами, настройку лимитов/таймаутов и последующую нагрузочную проверку.

## Тесты

Проверяются запуск/остановка, повторный запуск, отсутствие второго worker и агрегированная диагностика. Аппаратные испытания не выполнялись.
