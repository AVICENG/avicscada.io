# Интеграция расписаний с исполняемым FBD Core — DEV94

## Что добавлено

В библиотеку исполняемого `FBDService` добавлен блок **«Расписание станции» (`SCHEDULE`)**. Блок ссылается на сохранённое расписание Core по `schedule_id`, а не хранит собственную копию недельного календаря. При каждом вызове FBD Simulation или очередном цикле `FBDExecutionService` Core заново вычисляет значение через `ScheduleService.evaluate()`.

Поддерживаются типы расписания `BOOLEAN`, `NUMERIC`, `STRING` и `ENUM`. Для `BOOLEAN`, `NUMERIC` и `STRING` тип выхода проверяется при соединении с другими FBD-блоками. Для `ENUM` тип значения проверяется фактически во время вычисления принимающего блока.

## Защита и границы

- Блок нельзя сохранить без ссылки на существующее расписание.
- Расписание должно принадлежать той же станции, что и FBD-стратегия. Межстанционные ссылки отклоняются.
- В диагностике блока сохраняются ID и имя расписания, его ревизия, источник значения, часовой пояс, местное время, UTC-время вычисления и ближайшее изменение.
- Расписание выдаёт **намерение/значение для логики**, но не записывает значение в физическую точку. `field_writes_performed=false` и `runtime_published=false` остаются обязательными инвариантами.
- FBD-цикл использует монотонные часы для периодичности; вычисление календаря выполняется `ScheduleService` по часовому поясу расписания.

## Как использовать в Core API

1. Создать расписание для нужной станции через `/api/schedules`.
2. Добавить в исполняемую FBD-стратегию блок `SCHEDULE` с `params.schedule_id`, равным ID созданного расписания.
3. Соединить `OUT` блока с совместимым входом, например `BOOL_OUTPUT` или `FLOAT_OUTPUT`.
4. Выполнить `/api/fbd/{document_id}/simulate` для разовой проверки или запустить циклический `FBDExecutionService`.
5. Посмотреть `node_diagnostics` — там будут источник значения и данные расписания.

Пример узла:

```json
{
  "type": "SCHEDULE",
  "name": "График работы AHU-01",
  "params": {"schedule_id": "<ID сохранённого расписания>"}
}
```

## Что ещё не подключено

DEV94 подключает `ScheduleService` к исполняемой модели `LogicDocument` / `FBDService`. Это **не означает**, что FBD Studio authoring-документ (`FBDStudioService`, сохраняемый через `/api/fbd-studio`) уже компилируется в эту исполняемую модель. Studio остаётся authoring-only до отдельного проверенного compiler adapter. Также расписание пока не отправляет команды в Point Runtime и полевые контроллеры: для этого нужны отдельные безопасные механизмы публикации, подтверждения, качества и прав доступа.
