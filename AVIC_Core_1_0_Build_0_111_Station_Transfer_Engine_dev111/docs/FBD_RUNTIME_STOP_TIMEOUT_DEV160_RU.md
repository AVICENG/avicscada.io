# DEV160 — ограничение времени остановки FBD Runtime

## Причина изменения

До DEV160 `tick_once()` удерживал блокировку стратегии на всём протяжении вычисления графа и публикации виртуальных FBD-точек. Команда `stop(timeout=...)` сначала пыталась получить ту же блокировку, поэтому заданный вызывающей стороной тайм-аут не ограничивал ожидание блокировки.

## Изменения

- Запрос остановки теперь устанавливает `stop_event` до ожидания блокировки стратегии.
- Получение блокировки выполняется с ограниченным временем ожидания.
- Если блокировка не получена в срок, стратегия переводится в `ERROR`, а результат явно сообщает, что остановка не подтверждена.
- После завершения вычисления worker проверяет `stop_event` до публикации выходов. Отменённый цикл не публикует устаревший результат в FBD Point Runtime.
- Добавлен регрессионный тест с намеренно задержанным вычислением; он проверяет ограниченное время ответа stop и состояние ERROR.

## Границы гарантии

Python не может безопасно принудительно прервать произвольный уже выполняющийся поток. Поэтому тайм-аут не означает, что зависший worker уничтожен. Он означает, что запрос остановки ограничен по времени, стратегия не объявляется штатно остановленной, а worker должен проверить отмену перед публикацией. Для реального зависания внутри нативного кода потребуется изоляция вычислений в отдельном процессе.

## Проверка

Новый тест: `test_stop_timeout_is_honored_when_fbd_evaluation_holds_strategy_lock`.

Полный CI для коммита DEV160 ожидает завершения. До завершения Windows и Linux матрицы изменение не считается принятым.
