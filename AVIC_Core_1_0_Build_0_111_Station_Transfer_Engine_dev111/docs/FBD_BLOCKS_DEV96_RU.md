# Новые блоки FBD Core и компилятора Studio — DEV96

## Поддерживаемые блоки

| Блок | Входы Core | Выход | Семантика |
|---|---|---|---|
| SUB | A: float, B: float | OUT: float | A − B |
| MUL | A: float, B: float | OUT: float | A × B |
| DIV | A: float, B: float | OUT: float | A / B; если B = 0, симуляция выдаёт диагностическую ошибку |
| SELECT | SEL: bool, A: float, B: float | OUT: float | SEL=TRUE → A; SEL=FALSE → B |

## Работа с блоками

1. Разместите блок в FBD Studio.
2. Подключите выходы к соответствующим входам. Для `SELECT` подключите булевый сигнал к `SEL`, числовые сигналы — к `A` и `B`.
3. Сохраните проект.
4. Запустите **«Проверить и скомпилировать в Core…»**.
5. После успешной проверки создайте отдельную Core FBD-стратегию.
6. Выполните симуляцию Core-стратегии и проверьте выходы и диагностику узлов.

Компилятор проверяет количество и имена портов по контракту Core. Проверка совместимости типов и занятости входных портов выполняется также при сохранении Core-графа.

## Ошибки и безопасность

- Деление на ноль блокируется; AVIC не возвращает `Infinity` или `NaN` как допустимый результат.
- `SELECT.SEL` должен иметь тип BOOL.
- `SELECT.A` и `SELECT.B` должны иметь тип FLOAT.
- Значения всех числовых входов должны быть конечными числами.
- Новые блоки работают в режиме симуляции. `field_writes_performed=false`, `runtime_published=false`.

## Ограничения DEV96

`SCALE` в FBD Studio имеет однопортовый интерфейс `IN` и отдельные параметры диапазонов, тогда как текущий контракт Core `SCALE` требует пять входов. Поэтому этот блок не включён в компилятор до согласования модели параметров и портов. Stateful-блоки `HYSTERESIS`, `DELAY` и `LATCH` также остаются неподдерживаемыми компилятором до внедрения корректного жизненного цикла состояния в циклическом Runtime.
