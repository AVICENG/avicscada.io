# DEV209 — Общий Debounce Engine для дискретных точек

## Назначение

Добавлен транспортно-независимый механизм подавления дребезга бинарных входов. Он предназначен для общего применения после адаптеров BACnet, Modbus, MQTT и будущих протоколов, чтобы фильтрация не зависела от конкретного драйвера.

## Поведение

- Первый достоверный sample инициализирует состояние сразу, без искусственной задержки старта.
- Для переходов OFF→ON и ON→OFF задаются независимые задержки `on_ms` и `off_ms`.
- Краткий импульс отменяется, если вход вернулся к стабильному значению до дедлайна.
- Устойчивый переход принимается по истечении интервала.
- `flush_due(now=...)` завершает переход даже при отсутствии следующего sample.
- `cancel_pending(point_id)` позволяет отменить переход при потере качества/связи.
- Временные метки должны быть timezone-aware; старые измерения отклоняются.
- Состояния и конфигурации изолированы по point_id.

## Важная граница интеграции

DEV209 добавляет и тестирует state machine, но сам по себе ещё не включает фильтр в production `PointRuntimeService.publish`. Следующий шаг — подключить конфигурацию к Point Manager, запуск `flush_due` к общему Runtime scheduler и публикацию только принятых переходов в PointRuntime/Alarm/FBD/History. Нельзя подключать фильтр только в отдельных протокольных адаптерах: это создаст разное поведение между BACnet, Modbus и MQTT.

Механизм не создаёт собственный timer thread и не скрывает состояние качества. Неподтверждённый переход не должен порождать alarm/edge/event или команду.

## Проверки

`tests/test_signal_debounce_engine.py` покрывает короткий импульс, ON/OFF интервалы, commit по таймеру без нового sample, отмену при потере качества, изоляцию точек, невалидные значения и временные метки. Полный CI ещё должен подтвердить выполнение на Windows/Linux.
