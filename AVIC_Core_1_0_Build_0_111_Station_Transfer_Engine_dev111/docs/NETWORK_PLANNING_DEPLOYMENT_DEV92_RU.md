# Network Planning & Deployment — DEV92

## Зачем это нужно

Инженер должен иметь возможность проектировать сеть и адресацию будущего диспетчерского компьютера до подключения к объекту. Разработка на ноутбуке не должна заставлять проект запоминать IP ноутбука как единственно возможный адрес станции.

## Две формы сетевой конфигурации

### 1. Автоматическая привязка (`addressing_mode=auto`)

- Инженер выбирает реально существующий активный IPv4-интерфейс компьютера.
- AVIC сохраняет идентификатор интерфейса, его текущий IPv4 и подсеть.
- Рекомендация адаптера не является принудительным выбором: VPN и виртуальные интерфейсы остаются видимыми.
- Создание конфигурации не меняет IP компьютера и не запускает Discovery.

### 2. Ручной проектный план (`addressing_mode=manual`)

- Инженер задаёт IP будущей станции AVIC, CIDR-подсеть, необязательный шлюз и до четырёх DNS-адресов.
- Сеть сохраняется без локального интерфейса: проект можно создавать вне объекта.
- IP станции и шлюз проверяются на принадлежность заданной подсети; адрес станции не может совпадать с сетевым, broadcast или адресом шлюза.
- DNS проверяется как IPv4.
- AVIC не меняет настройки Windows, DHCP, маршрутизатора, NAT или полевых устройств.

## Проверка развёртывания

`GET /api/network/{network_id}/deployment-check` сравнивает сохранённый проектный IP/подсеть с активными интерфейсами текущего компьютера:

- `BOUND` — найден интерфейс с точным проектным IP и подсетью.
- `SUBNET_PRESENT_ADDRESS_MISMATCH` — подсеть есть, но IP текущего компьютера отличается от проектного.
- `PLANNED_NOT_PRESENT` — соответствующая подсеть не найдена.

Проверка read-only. Она не назначает IP и не перенастраивает интерфейс. Перед пуском IT/сетевой инженер должен назначить проектный адрес штатными средствами ОС/сетевой инфраструктуры, после чего AVIC проверяет совпадение.

## Диагностика IP

`POST /api/network/ping` выполняет один ICMP Echo к одному явно указанному IPv4 адресу. Тайм-аут ограничен диапазоном 0.1–3 секунды. Подсети не сканируются. Если ICMP запрещён, отсутствие ответа не доказывает недоступность устройства: следует дополнительно проверить нужный TCP-порт и прикладной протокол.

В дереве станции для сети доступны команды:
- Проверить привязку на этом ПК.
- Ping IP станции.

## Маршрутизация и разные подсети

- В одной инженерной системе могут быть несколько сетей и подсетей.
- IP устройства не обязан совпадать с подсетью интерфейса AVIC, если на объекте настроена маршрутизация.
- Modbus TCP использует обычную IP-маршрутизацию до адреса и порта.
- BACnet/IP broadcast discovery выполняется в локальном сегменте выбранного интерфейса; маршрутизируемое обнаружение требует корректной BACnet-инфраструктуры (например, BBMD/Foreign Device Registration).
- Явная unicast-инспекция BACnet может обращаться к удалённому IPv4 через таблицу маршрутизации ОС; реальный доступ зависит от маршрутизаторов, ACL, BBMD и настроек BACnet/IP.
- AVIC не присваивает устройствам новые IP через шлюз и не предполагает, что любой шлюз выполняет NAT или маршрутизацию.

## Инженерная иерархия

`Project → Station → PhysicalNetwork → ProtocolChannel → Device → Point`.

Сеть — сегмент/интерфейс и его адресный план. Канал — протокол (например, BACnet/IP или Modbus TCP). Устройство — конкретный узел с адресом. Станция AVIC может иметь несколько сетевых подключений; одна сеть может содержать устройства с разными протоколами через соответствующие каналы.

## API DEV92

- `GET /api/network/interfaces` — обнаружение активных IPv4 интерфейсов (read-only).
- `POST /api/stations/{station_id}/networks` — создание auto или manual сети.
- `GET /api/network/{network_id}/deployment-check` — проверка привязки плана к текущему компьютеру.
- `POST /api/network/ping` — один ограниченный ICMP probe.

## Ограничения DEV92

- Не реализовано автоматическое изменение IP Windows, DHCP, gateway, VLAN, NAT или маршрутов.
- Нет массового сканирования диапазонов; это намеренно исключено из первого безопасного шага.
- Список локальных интерфейсов пока не показывает полный набор системных маршрутов, DHCP lease и DNS-конфигурацию ОС.
- `Ping` не является подтверждением доступности BACnet/Modbus и не определяет производителя устройства.
- Для ручной сети полевой опрос/импорт разрешается только после фактической привязки текущего компьютера к точному проектному IP и подсети.
- Маршрутизируемый BACnet unicast не заменяет настройку BBMD/Foreign Device Registration и не гарантирует доступность.
- Устройства не перенастраиваются и не перепрограммируются.
