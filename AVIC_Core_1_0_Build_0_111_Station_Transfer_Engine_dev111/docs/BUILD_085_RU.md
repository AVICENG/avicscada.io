# DEV85 — Engineering Tree и Point Runtime

## Цель
Сделать единый доступ к инженерным объектам из любого рабочего пространства и ввести единый сервис текущих значений точек, чтобы драйверы разных протоколов не создавали собственные несовместимые механизмы передачи значений в FBD и другие подсистемы.

## Общая навигация и инженерное дерево
Общий шаблон `render_workspace` формирует одинаковую левую панель для Home, FBD, Graphics и Web Pages. Значок инженерного дерева открывает общую панель, получающую данные из `/api/engineering/tree`.

Дерево отображает:
- Проект → Станция;
- Физическая сеть → канал протокола → устройство → физические точки;
- FBD-проект → страницы → FBD-точки.

Физическая точка передаётся в FBD через существующий drag payload `point`, FBD-точка — через `fbd-point`. При открытии FBD-страницы формируется URL с `station`, `document`, `page`.

Это общий навигационный компонент, но специализированные внутренние панели редакторов не удалены: FBD сохраняет свои команды и библиотеку блоков, Graphics — инструменты мнемосхем, Web Pages — редактор страниц.

## Point Runtime
`avic_core.points.PointRuntimeService` использует существующий `Point` как единственную идентичность и место хранения последнего значения. Новый отдельный объект-клон для FBD не создаётся.

### Контракт
- `read(point_id)` — чтение последнего значения, качества, timestamp, единицы и источника.
- `snapshot(station_id=...)` — снимок текущих точек станции.
- `publish(point_id, value, quality, timestamp, source_driver_id)` — публикация измерения драйвером/адаптером.
- `subscribe(point_id, callback)` и `unsubscribe(...)` — подписки потребителей.

`publish` валидирует тип данных и качество, запрещает NaN/Infinity для чисел, требует timezone-aware timestamp, не принимает измерение в OUTPUT-точку и проверяет принадлежность указанного драйвера устройству, если у устройства задан `driver_instance_id`.

Обновление сохраняется в репозитории с optimistic concurrency. Подписчики вызываются после фиксации; ошибка одного подписчика не отменяет сохранённое обновление.

### FBD
- `FBDService.simulate` получает `POINT_INPUT` через `core.point_runtime.read`.
- Качество, отличное от GOOD, блокирует использование точки в симуляции.
- FBD Studio опрашивает read-only runtime API каждые 2 секунды и показывает текущее значение и качество на привязанных блоках.
- Отображение чисел — два знака после запятой по умолчанию, внутренняя точность остаётся исходной.

## Границы реализации
Point Runtime — это общий сервис значений, а не BACnet/Modbus драйвер и не самостоятельный сетевой опросчик. В DEV85 не запускаются сетевые соединения и не отправляются команды. Существующие BACnet IP Client и Modbus TCP Client пока не подключены к publish циклу. Следующий этап — драйверные адаптеры с явной конфигурацией, управляемым запуском, безопасным polling, качеством/таймаутами и отдельным Command Manager для записи.

## Приёмка и проверка
См. `BUILD_TEST_LOG_DEV85_RU.md`. В частности, тестируются:
- проверка типа/качества/времени и принадлежности драйвера;
- публикация, чтение, снимок и подписки;
- запрет входной публикации в OUTPUT;
- чтение FBD через Point Runtime;
- единая навигация и общее дерево во всех четырёх рабочих пространствах;
- контракт drag-and-drop физической/FBD-точки.
