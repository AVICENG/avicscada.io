# MQTT Runtime — DEV223

## Статус

В AVIC Driver Manager подключён отдельный событийный runtime MQTT на базе Paho MQTT 2.x. Драйвер работает только на чтение: подписывается на темы и передаёт разобранные значения в Point Runtime. Публикация команд через MQTT запрещена.

Поддерживаются MQTT 3.1.1 и MQTT 5.0, QoS 0/1/2, JSON и UTF-8 raw payload. Для JSON поддерживается путь через точку, например `sensors.temperature`; числовые значения могут иметь scale/offset. Размер payload ограничен 1 МиБ.

## Установка

```powershell
python -m pip install -e ".[mqtt]"
```

В составе extra устанавливается `paho-mqtt>=2.0,<3`. Без установленного extra попытка запуска MQTT-драйвера завершится понятной ошибкой; импорт базового AVIC Core не требует Paho.

## Конфигурация экземпляра

Допустимые поля:

- `host` — обязательное DNS-имя или IP брокера;
- `port` — порт брокера; по умолчанию 1883 без TLS и 8883 при заданном CA;
- `keepalive` — 10–3600 секунд, по умолчанию 60;
- `protocol` — `3.1.1` (по умолчанию) или `5.0`;
- `client_id` — необязательный Client ID; иначе генерируется из ID экземпляра;
- `tls_ca_certs` — путь к CA PEM-файлу для проверки сертификата брокера;
- `bindings` — непустой массив привязок точек.

Пример:

```json
{
  "host": "192.0.2.10",
  "port": 8883,
  "protocol": "5.0",
  "tls_ca_certs": "C:/AVIC/certs/mqtt-ca.pem",
  "bindings": [
    {
      "point_id": "00000000-0000-4000-8000-000000000001",
      "topic": "building/ahu-01/temperature",
      "qos": 1,
      "payload_format": "json",
      "value_path": "value",
      "scale": 1.0,
      "offset": 0.0
    }
  ]
}
```

Пример JSON-сообщения: `{"value": 22.5}`.

## Безопасность и ограничения DEV223

- Пароли, токены, приватные ключи и другие секреты запрещено помещать в конфигурацию DriverInstance.
- На этом этапе MQTT username/password и клиентский TLS private key не подключены к SecretStore. Для брокера с аутентификацией требуется отдельное безопасное внедрение секретов; не обходить ограничение передачей пароля в JSON.
- При заданном CA проверяется цепочка сертификата; отключение проверки имени/сертификата не поддерживается.
- Без TLS соединение идёт открытым текстом; использовать его только в доверенной изолированной сети.
- Драйвер не публикует сообщения и не выполняет управляющие команды.
- Поддержка live broker acceptance, переподключения под нагрузкой и проверки на реальном брокере остаётся обязательным этапом перед производственной готовностью.
- MQTT runtime событийный: он не создаёт polling loop и переводит состояние в DEGRADED, пока брокер не подключён.

## Проверки

Набор `tests/test_mqtt_runtime_dev223.py` проверяет подписки с объединением QoS по теме, декодирование JSON и масштабирование, BAD_CONFIGURATION при ошибочном payload, а также жизненный цикл событийной сессии. Эти тесты используют изолированный fake-клиент; они не заменяют тест с Mosquitto/EMQX или реальным брокером.
