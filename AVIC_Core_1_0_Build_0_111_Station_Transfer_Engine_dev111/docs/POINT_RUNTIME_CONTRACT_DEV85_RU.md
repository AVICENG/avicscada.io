# Point Runtime Contract — DEV85

## Назначение
`PointRuntimeService` — единая точка обмена текущими значениями между протокольными адаптерами и подсистемами AVIC. Сервис не знает BACnet Object Identifier, Modbus register address или OPC UA NodeId: это остаётся ответственностью драйвера.

## Идентичность
- `point_id` — неизменяемый внутренний UID объекта `Point`.
- `native_identity` / `source_ref` — исходная идентичность объекта в протоколе.
- `device_id` — внутренний UID устройства AVIC.
- `driver_instance_id` — владелец точки на стороне AVIC, если назначен.

Драйвер публикует значение в существующий `point_id`. Он не создаёт новую точку при каждом обновлении. FBD и остальные потребители читают тот же объект.

## Значение и качество
Каждая публикация содержит `value`, `quality`, `timestamp`. Значения проходят проверку типа, числа должны быть конечными. Timestamp должен включать часовой пояс. Качество `GOOD` требуется для FBD-симуляции; `UNCERTAIN`, `STALE`, `BAD_COMMUNICATION`, `BAD_CONFIGURATION` и `DISABLED` не считаются пригодными для расчёта.

## Направление
`publish` предназначен для входных измерений и запрещает публикацию в точку с направлением `OUTPUT`. Запись команды в контроллер — отдельный будущий Command Manager и не реализована этим сервисом.

## API
- `GET /api/points/{point_id}/runtime`
- `GET /api/engineering/points/runtime?station_id=<uuid>`

Оба API только читают данные. Публичного HTTP endpoint для произвольной публикации/записи в DEV85 нет.

## Подписки
`subscribe` регистрирует callback на UID точки. `publish` фиксирует значение, затем вызывает callbacks вне lock. Исключения callbacks изолируются и сохраняются в диагностическом списке сервиса.

## Важное ограничение
В DEV85 драйверы BACnet/Modbus ещё не подключены к `publish`. Это контракт для интеграции, а не доказательство реального обмена с оборудованием. Не использовать DEV85 как средство записи команд в полевые контроллеры.
