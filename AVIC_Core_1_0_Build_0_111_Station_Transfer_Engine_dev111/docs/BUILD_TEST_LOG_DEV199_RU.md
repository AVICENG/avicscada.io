# AVIC Core 1.0 — журнал DEV199

## Цель цикла
Разобрать фактический отказ CI DEV198, исправить первопричину и продолжить общий круг качества.

## Результат проверки DEV198
- Linux Python 3.11 и 3.13: 31 345 тестов прошли, 2 упали.
- Linux Python 3.12: 31 345 тестов прошли, те же 2 упали.
- Сбой не в Scheduler и не в новом учёте лицензии. Linux падения возникли в BACnet Device Import: после усиления проверки целостности графа импортированный DriverInstance ссылался на package_id=bacnet-ip, но в репозитории не было записи DriverPackage.
- Windows дополнительно выявил ошибку ACL установки: `icacls` фактически оставлял ACE Local Account вместо явного SID текущего пользователя, хотя команда завершалась без ошибки.
- Установка зависимостей, pip check и compileall прошли на всех Linux jobs. Windows Python 3.11/3.12 также выявил проблему ACL; Python 3.13 job на момент анализа ещё выполнялся.
- Исправление Windows ACL: заменён косвенный вызов `icacls` на прямое формирование защищённого SDDL DACL и применение через Win32 `ConvertStringSecurityDescriptorToSecurityDescriptorW` + `SetFileSecurityW`. В ACL явно включены только текущий пользователь, Local System и Builtin Administrators; Local Account не добавляется.
- После первичного исправления продолжен следующий участок: добавлена конфигурация архивирования точек History с регистрацией usage в общей лицензии.

## Исправление DEV199
- DeviceImportService теперь регистрирует встроенный DriverPackage BACnet/IP (версия 1.0, vendor AVIC, signature_status BUILTIN), если такой пакет ещё не установлен, и только затем создаёт DriverInstance.
- Повторный импорт не создаёт дубликат записи пакета.
- Существующая проверка импортированной точки остаётся: discovered/imported Point получает licensed_active=false и не расходует лицензионный лимит.
- Усилен тест импорта: проверяет наличие записи встроенного пакета BACnet/IP.

## Проверки
- Исправление BACnet package import и Windows ACL отправлено в PR #5.
- Новый полный CI должен повторно прогнать матрицу Python 3.11/3.12/3.13 на Linux и Windows.
- Для History добавлены постоянные bindings `history_bindings`, API включения/отключения архивирования точки и тесты на лицензионный отказ, освобождение usage и запрет межстанционной привязки.
- Для Alarm учёт привязан к постоянным доменным объектам `Alarm`: Point-backed rule активирует точку в той же транзакции CoreObjectService, изменение источника и удаление правила снимают ссылку. Транзиентные события AlarmService не расходуют лицензию.
- CoreObjectService теперь блокирует удаление Point, пока у него есть активные `licensed_usage`; пакетное удаление Alarm rules сначала снимает их usage в той же транзакции.
- Дополнительно закрыт сценарий атомарного удаления Alarm и его source Point одним optimistic batch: ссылка Alarm не заставляет предварительно менять версию удаляемой точки, поэтому исходные версии обоих объектов остаются валидными. Добавлен регрессионный тест.
- Исправлена тонкость базовой активности: после удаления последней инженерной ссылки точка возвращается к исходному состоянию активности (в том числе legacy-физические точки остаются активными). `save_graph` возвращает актуальные версии Point после автоматической регистрации usage.
- History использует общий ключ `history:<station_id>` с полным набором архивируемых точек станции; запись отдельных samples сама по себе не расходует дополнительные слоты.
- Добавлена startup-reconciliation для независимых SQLite-каталогов History/Core: при запуске Core восстанавливаются потерянные usage-ссылки, снимаются осиротевшие ключи `history:` и удаляются недействительные межстанционные bindings. Это идемпотентный компенсирующий протокол, не общая ACID-транзакция.
- Добавлены тесты восстановления после частичного сбоя, освобождения фантомного usage и очистки устаревшей межстанционной привязки.
- До завершения нового CI статус DEV199 — ожидает подтверждения. Локальный Windows acceptance в этой среде не запускался.
