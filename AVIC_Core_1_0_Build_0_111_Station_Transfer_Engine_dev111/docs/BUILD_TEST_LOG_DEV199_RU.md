# AVIC Core 1.0 — журнал DEV199

## Цель цикла
Разобрать фактический отказ CI DEV198, исправить первопричину и продолжить общий круг качества.

## Результат проверки DEV198
- Linux Python 3.11 и 3.13: 31 345 тестов прошли, 2 упали.
- Linux Python 3.12: 31 345 тестов прошли, те же 2 упали.
- Сбой не в Scheduler и не в новом учёте лицензии. Оба падения возникли в BACnet Device Import: после усиления проверки целостности графа импортированный DriverInstance ссылался на package_id=bacnet-ip, но в репозитории не было записи DriverPackage.
- Установка зависимостей, pip check и compileall прошли на всех упавших Linux jobs. Windows jobs ещё выполнялись на момент анализа логов.

## Исправление DEV199
- DeviceImportService теперь регистрирует встроенный DriverPackage BACnet/IP (версия 1.0, vendor AVIC, signature_status BUILTIN), если такой пакет ещё не установлен, и только затем создаёт DriverInstance.
- Повторный импорт не создаёт дубликат записи пакета.
- Существующая проверка импортированной точки остаётся: discovered/imported Point получает licensed_active=false и не расходует лицензионный лимит.
- Усилен тест импорта: проверяет наличие записи встроенного пакета BACnet/IP.

## Проверки
- Исправление отправлено в PR #5.
- Новый полный CI должен повторно прогнать матрицу Python 3.11/3.12/3.13 на Linux и Windows.
- До завершения нового CI статус DEV199 — ожидает подтверждения. Локальный Windows acceptance в этой среде не запускался.

## Следующий круг
- Проверить все шесть CI jobs, включая Windows.
- Затем подключить лицензионный usage к реальным конфигурациям Alarm и Historian, а не к transient alarm/history событиям.
- Проверить единый уникальный учёт при одновременном использовании точки в FBD, Graphics, Scheduler, Alarm и Historian.

## Статус
Исправлена выявленная регрессия целостности импорта BACnet. DEV199 не объявляется завершённым до зелёной CI-матрицы.
