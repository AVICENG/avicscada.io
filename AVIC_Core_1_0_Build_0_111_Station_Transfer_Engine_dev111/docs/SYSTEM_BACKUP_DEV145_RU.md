# DEV145 — Системное резервирование AVIC

## Цель

Добавлен отдельный механизм полной резервной копии установки AVIC Core. Он не подменяет перенос инженерной станции (.avicstation) и не смешивается с прежним файловым Project Backup.

## Реализовано в DEV145

- SystemBackupManager — отдельная служба полной системной копии.
- CoreApplication.create_system_backup(...) — создание зашифрованной копии.
- CoreApplication.inspect_system_backup(...) — проверка пароля, формата, состава и контрольных сумм до восстановления.
- CoreApplication.restore_system_backup(...) — восстановление в новый или пустой каталог данных.
- CoreApplication.list_system_backups() — список локальных архивов с SHA-256 и размером.
- CoreApplication.prune_system_backups(keep_last=...) — безопасная политика поколений, сохраняющая заданное число последних архивов.
- Шифрование всего архива AES-256-GCM; ключ выводится из пароля через Scrypt. Пароль не сохраняется в AVIC.
- Снимки SQLite создаются штатным SQLite Online Backup API, а не простым копированием открытых .sqlite3 файлов.
- После создания и перед восстановлением проверяются SHA-256, размеры, список файлов и целостность SQLite.
- Запрещены небезопасные пути, повторяющиеся имена, символические ссылки и превышение лимитов архива.
- Восстановление выполняется во временный каталог; целевой каталог заменяется только после полной проверки.
- Резервная копия не включает сам каталог backups, чтобы архивы не попадали внутрь следующих архивов.

## Пример

```python
from avic_core.application.container import CoreApplication

with CoreApplication(r"C:\AVIC\data") as core:
    backup = core.create_system_backup(
        passphrase="длинный-пароль-резервной-копии"
    )
    preview = core.inspect_system_backup(
        backup,
        passphrase="длинный-пароль-резервной-копии",
    )
    print(preview.backup_id, preview.file_count, preview.databases)

    core.restore_system_backup(
        backup,
        r"D:\AVIC\recovered-data",
        passphrase="длинный-пароль-резервной-копии",
        expected_backup_id=preview.backup_id,
    )
```

## Важные ограничения — не считать закрытыми

1. Все станции и сессии драйверов должны быть остановлены. Создание системной копии при работающей станции блокируется.
2. SQLite Online Backup гарантирует согласованность каждой отдельной базы. DEV145 ещё не вводит единый глобальный write barrier между всеми SQLite-хранилищами. Поэтому снимки разных БД не являются одной общей атомарной транзакцией.
3. Восстановление выполняется в новый или пустой каталог. Оно не перезаписывает работающий экземпляр AVIC и не выполняет горячую замену файлов.
4. Автоматический планировщик, удалённое хранилище, проверка восстановления по расписанию и централизованный Provisioning Manager ещё не реализованы. Каталог локальных архивов и ручная политика retention по количеству поколений добавлены.
5. Station Transfer DEV111 уже переносит инженерную конфигурацию отдельной станции, но его UI, транспорт удалённого развёртывания, автоматическое сопоставление оборудования и активация ещё не завершены.
6. Миграция форматов AVIC между версиями остаётся отдельной задачей. Миграция Niagara AX/N4 в AVIC не планируется.
7. Системная копия содержит защищённые данные установки и должна храниться в безопасном месте. Пароль восстановления должен храниться отдельно от архива.

## Принцип дальнейшего развития

- System Backup — полное восстановление той же установки AVIC.
- Station Transfer / Clone — передача инженерной конфигурации на другой AVIC без переноса сетевых секретов и площадочных адресов.
- Deployment Manager — проверка, подготовка, ввод в эксплуатацию и откат.
- Provisioning Manager — массовые и плановые задания для нескольких станций.
- Migration Engine — последовательное обновление форматов AVIC с preview, журналом и предварительной резервной копией.

Эти механизмы остаются раздельными службами с общим журналом операций и единым интерфейсом Workbench.
