# FBD Core — SCALE и HYSTERESIS (DEV97)

## SCALE

Порты Core:

| Порт | Тип | Назначение |
|---|---|---|
| IN | float | Текущее измеренное значение |
| IN_MIN | float | Нижняя граница входного диапазона |
| IN_MAX | float | Верхняя граница входного диапазона |
| OUT_MIN | float | Нижняя граница выходного диапазона |
| OUT_MAX | float | Верхняя граница выходного диапазона |
| OUT | float | Результат преобразования |

Формула:

`OUT = OUT_MIN + ((IN - IN_MIN) / (IN_MAX - IN_MIN)) * (OUT_MAX - OUT_MIN)`

Если `clamp_output=true`, результат ограничивается диапазоном между OUT_MIN и OUT_MAX (в том числе при обратном диапазоне). `IN_MIN == IN_MAX` запрещён. Все входы должны быть конечными числами.

В FBD Studio пользователь задаёт IN_MIN/IN_MAX/OUT_MIN/OUT_MAX в `params.scale`; компилятор создаёт для этих параметров отдельные FLOAT_INPUT-узлы Core и связи к соответствующим портам. Studio-порт IN остаётся единственным сигнальным входом. По умолчанию `clampOutput=true`, как в текущем редакторе.

## HYSTERESIS

Порты Core:

| Порт | Тип | Назначение |
|---|---|---|
| IN | float | Измеренное значение |
| LOW | float | Нижний порог отключения |
| HIGH | float | Верхний порог включения |
| OUT | bool | Состояние выхода |

Правила:

- если предыдущее состояние OFF и `IN >= HIGH`, выход становится ON;
- если предыдущее состояние ON и `IN <= LOW`, выход становится OFF;
- между LOW и HIGH сохраняется предыдущее состояние;
- требуется `LOW < HIGH`;
- `initial_state` задаёт начальное состояние при первом расчёте в новом поколении стратегии.

В FBD Studio пороги задаются в `params.hysteresis`. Если соответствующий порт не соединён, компилятор создаёт входную константу из настройки. Если порт явно соединён, пользовательская связь имеет приоритет.

## Состояние и ошибки

`FBDService.simulate(..., runtime_state=state)` принимает словарь состояния, индексированный ID узла. Словарь обновляется только после успешного завершения всего графа. `FBDExecutionService` хранит такой словарь в памяти между тиками. При новом `start()` состояние очищается и восстанавливается из начальных параметров блоков.

Если `LOW >= HIGH`, диапазон SCALE нулевой, входы не конечны или другой блок выдаёт ошибку, тик завершается ошибкой. Никакие частичные обновления состояния не фиксируются. В DEV97 отсутствуют публикация FBD в Point Runtime и физические команды контроллерам.


## KNOB и CONSTANT (DEV186)

Оба блока имеют один выход `OUT: float` и не имеют входов.

| Блок | Параметр | Значение по умолчанию | Назначение |
|---|---|---:|---|
| KNOB | `value` | 50.0 | Ручной числовой источник для задания/проверки уставки |
| CONSTANT | `value` | 1.0 | Фиксированная числовая константа |

В редакторе откройте свойства блока и задайте конечное числовое значение. Значения bool, NaN, Infinity и текстовые значения не принимаются компилятором. KNOB может быть переопределён через словарь входов диагностической симуляции; это тестовый override, а не команда оператору и не запись в контроллер. CONSTANT не переопределяется и сохраняет заданное значение.

Оба блока проходят путь Studio → compile-preview → Core FBD → simulation. Компиляция создаёт отдельную Core-стратегию; автоматическая публикация и физические записи не выполняются.


## COMBINATION (DEV187)

Порты: `E`, `F`, `G`, `H` — BOOL; `OUT` — BOOL.

В свойствах блока задаются четыре строки условий. В каждой строке можно включить/отключить строку и для каждого входа выбрать состояние:
- заглавная буква (например, `E`) — вход должен быть TRUE;
- строчная буква (например, `e`) — вход должен быть FALSE;
- пустая ячейка — вход не учитывается.

Сначала вычисляется AND всех непустых условий внутри каждой включённой строки, затем OR результатов включённых строк. Выключенные и полностью пустые строки дают FALSE. Неизвестные символы, неправильное количество строк или ячеек отклоняются. Реализация Core повторяет формулу редактора; физические записи не выполняются.


## DELAY и LATCH (DEV188)

### DELAY
Порты: `IN: bool`, `TIME: float`, `OUT: bool`. В свойствах задаются `delay.onDelay` и `delay.offDelay` в секундах. При TRUE на IN выход включается после onDelay; при FALSE выход выключается после offDelay. Если TIME соединён, он задаёт onDelay; иначе используется параметр. Core Runtime учитывает фактический интервал тика, а не условную частоту интерфейса. Задержки должны быть конечными и неотрицательными.

### LATCH
Порты: `SET: bool`, `RESET: bool`, `OUT: bool`. Состояние удерживается между тиками. При `resetPriority=true` одновременные SET и RESET дают RESET; при false приоритет имеет SET. Начальное состояние задаётся параметром `latch.initial`. Состояние принадлежит конкретному поколению исполняемой стратегии и сбрасывается при новом запуске.


## ANALOG_INPUT и EXTERNAL_SENSOR (DEV189)

Оба блока имеют один выход `OUT: float`, не имеют входов и хранят rawValue. Для калибровки в свойствах блока сохраняется массив `scalingPoints` — пары `[X, Y]`. Core сортирует точки по X и выполняет линейную интерполяцию между соседними точками; за пределами диапазона возвращает крайнее Y. Требуется 2–20 пар, все координаты конечны, значения X уникальны. Если указан Sensor Type, таблица обязательна.

Без Sensor Type и таблицы блок выдаёт rawValue без преобразования. Это виртуальный/симуляционный источник. Для фактического чтения BACnet/Modbus точек используйте POINT_INPUT и драйвер станции; эти блоки не являются сетевыми драйверами и не записывают в контроллер.


## PID_LOOP (DEV190)

Порты входа: `PV`, `SP`, `ENABLE`, `MANUAL`, `MANUAL_OUT`, `RESET`. Выходы: `OUT`, `P`, `I`, `D` — все FLOAT.

Параметры находятся в `params.pid`: Kp/Ti/Td, direct/reverse action, auto/manual, outputMin/outputMax, disabledOutput, manualOutput, bias, deadband, derivativeFilter, outputRateLimit, sampleTime, integralMin/integralMax. Core выполняет валидацию конечных значений и ограничений до сохранения/компиляции.

В AUTO используется ошибка SP−PV, D вычисляется по измерению PV, интегратор ограничивается и защищён conditional anti-windup. MANUAL отслеживает интегратор для безударного возврата в AUTO. Одновременный RESET сбрасывает интегральную/дифференциальную память. ENABLE=FALSE переводит блок в DISABLED и удерживает настроенный disabledOutput/последний выход. OUT/P/I/D доступны как отдельные именованные порты Core и могут использоваться в связях.
