# Компиляция FBD Studio в исполняемый FBD Core — DEV95

## Для чего это нужно

FBD Studio — редактор, в котором инженер размещает блоки и соединяет их проводами. До DEV95 сохранённый граф Studio не являлся исполняемой стратегией Core. DEV95 добавляет первый ограниченный и проверяемый переход между этими двумя представлениями.

## Как запустить проверку в интерфейсе

1. Откройте FBD-проект из дерева нужной станции.
2. Сохраните изменения в AVIC Core.
3. Откройте контекстное меню проекта правой кнопкой мыши или меню **File**.
4. Выберите **«Проверить и скомпилировать в Core…»**.
5. AVIC сначала проверит типы блоков, порты, ссылки на точки и расписания, а также допустимость связей.
6. Если есть ошибки, появится список причин. Исходная схема останется сохранённой.
7. Если проверка пройдена, AVIC попросит подтверждение создания отдельной Core FBD-стратегии.
8. После подтверждения будет показан ID созданной стратегии.

## Поддерживаемые блоки DEV95

| Блок Studio | Результат в Core | Условия |
|---|---|---|
| BOOL_INPUT | BOOL_INPUT | Значение Да/Нет |
| FLOAT_INPUT | FLOAT_INPUT | Конечное числовое значение |
| POINT_INPUT | POINT_INPUT | Нужна реальная точка этой же станции |
| SCHEDULE | SCHEDULE | Нужен `schedule_id` существующего расписания Core |
| AND / OR / NOT | AND / OR / NOT | Порты должны совпадать с контрактом Core |
| ADD | ADD | Порты должны совпадать с контрактом Core |
| COMPARE_GT / COMPARE_LT | COMPARE_GT / COMPARE_LT | Порты должны совпадать с контрактом Core |
| LIMIT | LIMIT | Входы IN, LOW, HIGH |
| BOOL_OUTPUT / FLOAT_OUTPUT | BOOL_OUTPUT / FLOAT_OUTPUT | Вход IN |

Компилятор не делает вид, что любой визуальный блок уже имеет реализацию в Core. Если тип блока или контракт портов не поддержан, компиляция прекращается с диагностикой.

## Что пока не компилируется

- PID_LOOP и COMBINATION.
- SUB, MUL, DIV, SCALE, SELECT, HYSTERESIS, DELAY, LATCH, SWITCH, KNOB, TIME, CONSTANT и другие блоки, пока отсутствующие в контракте исполняемого Core FBD.
- Локальный недельный календарь блока SCHEDULE из Studio, если он не связан с существующим Scheduler Manager расписанием Core.
- Межстраничные Connective и ссылки `references`.
- Экспортированные FBD Points: их публикация в Point Runtime ещё не реализована.

Это временное ограничение первой версии компилятора, а не удаление или порча исходных блоков. Исходный Studio-проект сохраняется как есть.

## API

### Предварительная проверка

`POST /api/fbd-studio/{document_id}/compile-preview`

Тело:

```json
{"expected_revision": 3}
```

Возвращает `compilable`, количество страниц/блоков/связей и список `issues`. Операций записи не выполняет.

### Компиляция

`POST /api/fbd-studio/{document_id}/compile`

Тело:

```json
{"expected_revision": 3}
```

При успехе возвращает `core_document`, число скомпилированных блоков и связей, `runtime_published=false` и `field_writes_enabled=false`.

## Защита от дублей и ошибок

- Проверяется ожидаемая ревизия Studio-документа. Устаревшая ревизия приводит к конфликту, а не к компиляции старых данных.
- Одна и та же ревизия компилируется идемпотентно: повторный запрос возвращает ту же Core-стратегию.
- При ошибке после создания документа выполняется очистка частично созданных узлов, связей и страниц.
- Созданная стратегия не запускается автоматически.
- Никакие физические команды не отправляются.
