# AVIC FBD — стандарт имён, обозначений и нумерации (DEV83)

## 1. Три независимых идентификатора

- `id` — неизменяемый UID объекта, используется связями, ссылками, историей и сохранением.
- `tag` — короткое инженерное обозначение, уникальное в пределах FBD-проекта.
- `name` — редактируемое человекочитаемое имя.

Изменение `name` или `tag` не должно менять UID и не должно переназначать связи на другой объект. Номер не переиспользуется после удаления: новый объект получает следующий свободный номер соответствующего типа.

## 2. Обозначения блоков

Автоматические префиксы: `PID`, `AI`, `DI`, `AO`, `DO`, `AND`, `OR`, `NOT`, `ADD`, `SUB`, `MUL`, `DIV`, `CMP`, `LIM`, `SCL`, `SEL`, `HYS`, `TON`, `LAT`, `SW`, `KNOB`, `TIME`, `CONST`, `LOGIC`, `CON`, `TO`.

Примеры: `PID_001`, `AI_001`, `AND_001`, `TON_001`. Номер присваивается автоматически при создании. При копировании блока создаётся новый UID, новый tag и новый номер; исходный блок не меняется. Tag уникален по всему FBD-проекту, а не только на одной странице.

## 3. FBD Points

Точки имеют отдельную последовательность по классу сигнала: `AI_001`, `DI_001`, `AO_001`, `DO_001`. Экспортируемый выход блока получает `AO` для аналогового сигнала или `DO` для дискретного. Входные классы зарезервированы для точек, импортируемых как источники.

Символьный адрес имеет форму `P1.PID_001.OUT`; путь — `FBD/P1.PID_001.OUT`. Он формируется из кода страницы, tag блока и имени порта. UID точки и UID исходного порта остаются первичными ссылками. Повторное назначение одной точки на тот же выход запрещено.

Старые `FBDP-0001` и старые блоки без tag мигрируют при загрузке: UID сохраняется, старый tag переносится в `legacy_tag`, новый tag выдаётся автоматически. Миграция не меняет связи и native identity.

## 4. Соединения

Постоянные соединения отображаются незамкнутыми SVG `polyline` с `fill=none`; отдельная прозрачная polyline служит только зоной выбора. Предпросмотр при перетаскивании использует SVG `path`, но также имеет `fill=none`. Маршрут ортогональный, углы 90°. В DEV81 постоянные линии уже были polyline с `fill=none`, поэтому исходная причина заливки не подтверждена только исходным кодом. DEV83 добавляет принудительный CSS-запрет заливки для всех `polyline` и `path` внутри слоя соединений.

## 5. Границы приёмки

Сервер проверяет уникальность module tags в пределах проекта. Клиентская миграция и генерация tag проверяются синтаксически и тестами. Проверка поведения указателя, попадания по линии и внешнего вида в Windows-браузере остаётся отдельным визуальным приёмочным этапом.
