# AVIC FBD — аудит полного покрытия блоков и зависимостей DEV185

Дата: 26.11.2026  
База исходников: DEV184, commit `7673c367182084bd41aea5d84efad9d67bc67df3`  
Актуальная ветка после настройки Linux CI: `ci/fbd-connective-compiler`

## 1. Вывод аудита

FBD Studio, Core FBD и Core Runtime пока не имеют единого полного каталога исполняемых блоков. В браузерном редакторе обнаружено 29 типов вычислительных/источниковых блоков. Core FBD и серверный компилятор Studio имеют общий ограниченный набор из 19 типов. Следовательно, 10 типов редактора нельзя считать сквозно реализованными.

CONNECTIVE и TO_CONNECTIVE не входят в эти 29 типов: это соответственно межстраничный сигнальный alias и навигационный маркер, а не самостоятельные вычислительные блоки.

## 2. Фактический каталог редактора

| Тип | Роль | Состояние сквозного пути на DEV184 |
|---|---|---|
| BOOL_INPUT | Виртуальный дискретный источник | Core + compiler |
| FLOAT_INPUT | Виртуальный аналоговый источник | Core + compiler |

| ANALOG_INPUT | Аналоговый источник/датчик с калибровкой | UI-only; Core compiler отсутствует |

| FLOAT_OUTPUT | Аналоговый результат | Core + compiler |

| AND | Логическое И | Core + compiler |

### Текущая граница

- Core `FBDService.BLOCKS`: 19 типов.
- `FBDStudioService._COMPILER_BLOCKS`: 19 типов.
- UI `defs`: 29 типов.
- Разрыв: ANALOG_INPUT, EXTERNAL_SENSOR, COMBINATION, PID_LOOP, DELAY, LATCH, SWITCH, KNOB, TIME, CONSTANT.

Наличие блока в UI или его локальной JavaScript-симуляции не означает, что блок исполняется в Core. Нельзя включать блок в список поддерживаемых до появления Core-контракта, компилятора, runtime-семантики и тестов.

## 3. Зависимости, которые должны быть закрыты

1. **Единый контракт блока:** стабильный type ID, категория, версия семантики, именованные входы/выходы, типы, значения по умолчанию, диапазоны параметров, statefulness, единицы измерения и диагностика.
2. **Типизация сигналов:** BOOL, FLOAT, INT, STRING, ENUM и безопасное разрешение динамических типов POINT_INPUT/SCHEDULE. Никакого неявного преобразования bool↔number или потери enum/string.
3. **Граф:** UID блоков/портов/линий, направление, существование endpoint, одна связь на вход (если блок явно не допускает fan-in), отсутствие циклов, детерминированный порядок.
4. **Многостраничность:** Connective/To Connective/Page Reference, Go To только навигация, проверка графа после раскрытия всех ссылок, сохранение quality/provenance.
5. **Параметры:** строгая схема и валидация значений, отсутствие NaN/Infinity, проверка диапазонов, версия схемы параметров и безопасная миграция.
6. **Состояние:** изоляция по стратегии и поколению Runtime; атомарное обновление state только после успешного тика; детерминированный reset/restart; тесты пропуска/повтора/ошибки тика.
7. **Источники данных:** POINT_INPUT только из той же станции и с GOOD quality; расписания только той же станции; датчики с проверенной таблицей/калибровкой и единицами; виртуальные входы не должны маскироваться под реальные точки.
8. **Безопасность исполнения:** компиляция отдельно от публикации; staged publish/rollback; RBAC/Command Manager/Point Quality; запрет полевых записей до отдельного разрешённого пути.
9. **Жизненный цикл:** копирование/переименование/удаление страниц, блоков, портов, ссылок и FBD Points; отчёт о зависимостях до destructive action; отсутствие orphan-объектов.
10. **Совместимость:** серверная валидация, UI editor, Core library, compiler, simulator и Runtime должны получать один контракт из общего каталога, а не поддерживать независимые списки.

## 4. Выявленные риски DEV184

- Редактор позволяет создавать больше типов, чем компилятор способен выполнить. Пользователь может построить визуально корректную схему, которая не компилируется.
- Core Runtime на DEV184 реализует stateful-семантику HYSTERESIS, но не полный набор stateful-блоков редактора.
- PID реализован в JavaScript-редакторе и проверяется тестами исходного текста UI; это не доказывает наличие эквивалентного Core PID execution.
- SWITCH имеет UI-описание, но отдельная исполняемая формула не подтверждена.
- ANALOG_INPUT/EXTERNAL_SENSOR требуют переносить в Core калибровку, sensor catalog, единицы и проверку границ, а не только добавлять тип блока.
- SCHEDULE должен сохранять реальные типы значения Scheduler Manager; текущая UI-заглушка SCHEDULE по умолчанию описана как BOOL.
- Серверная проверка документа и компилятор должны проверять одну и ту же схему данных. Проверка только в браузере недостаточна.

## 5. План закрытия

### Этап A — контракт и регрессия
- Ввести единый реестр блоков и формальные схемы портов/параметров.
- Добавить тест, сравнивающий типы редактора, Core и компилятора.
- Добавить отрицательные тесты на неизвестные типы, неверные порты, динамические типы, некорректные параметры и подмену данных.
- Обновить документацию и таблицу совместимости.

### Этап B — базовые и источниковые блоки
- Перенести CONSTANT, KNOB и TIME в Core с безопасными и однозначными контрактами.
- Завершить ANALOG_INPUT/EXTERNAL_SENSOR с калибровкой, единицами, provenance и ограничениями.
- Сверить SCHEDULE по всем типам значения Scheduler Manager.

### Этап C — логика и stateful blocks
- Перенести COMBINATION, DELAY, LATCH и определить/реализовать SWITCH.
- Реализовать PID_LOOP в Core с детерминированным временем тика, ограничением выхода, anti-windup, derivative filter, manual/auto transfer и reset.
- Все stateful-блоки должны использовать runtime_state стратегии, не состояние UI.

### Этап D — сквозная многостраничность и жизненный цикл
- Проверить локальные связи и Connective в общем графе.
- Проверить Go To как чистую навигацию.
- Закрыть копирование, удаление, перенос, импорт/экспорт и очистку зависимостей.
- Проверить FBD Points, graphics bindings, quality и provenance.

### Этап E — валидация
- Полный pytest на Linux и Windows.
- Python 3.11, 3.12, 3.13 на Linux; системный Python Windows Runner.
- compileall, pip check, тесты браузерной логики, API, Core simulation и cyclic Runtime.
- Регрессионные сценарии: минимум 1 блок каждого типа, все пары совместимых/несовместимых портов, длинные графы, циклы, несколько страниц, отказ блока посреди тика, restart, duplicate/delete, stale revision и повторная компиляция.

## 6. Критерий готовности

FBD нельзя объявить завершённым, пока каждый тип, доступный инженеру в редакторе, не имеет проверенного Core-контракта и исполняемой семантики либо не исключён из доступной библиотеки с явным объяснением. Для каждого поддерживаемого типа должны проходить тесты создания, сохранения, проверки портов, компиляции, симуляции, циклического исполнения (если stateful), диагностики, копирования и удаления.

Ни один этап не включает автоматическую публикацию или запись в физические контроллеры. Эти операции остаются отдельным защищённым процессом.


## 13. Изменения DEV186 — числовые источники

В DEV186 добавлены первые два ранее отсутствовавших сквозных блока:

- `KNOB`: ручной числовой источник с типом выхода FLOAT; значение хранится в параметрах блока. В режиме симуляции допускается переопределение входного значения через тестовый набор входов. Это не является командой физическому контроллеру.
- `CONSTANT`: числовой источник-константа с типом выхода FLOAT.

Оба блока добавлены в Core FBD catalog, серверную проверку FBD Studio, compiler mapping и Core simulation. Для значений применяется строгая проверка: bool, NaN, Infinity и нечисловые значения отклоняются. Компиляция остаётся отдельной от публикации; полевые записи выключены.

**Покрытие после DEV186:** 21 из 29 типов редактора имеют контракт в Core и путь компиляции; 8 типов остаются неподдержанными сквозным путём: ANALOG_INPUT, EXTERNAL_SENSOR, COMBINATION, PID_LOOP, DELAY, LATCH, SWITCH, TIME. Наличие локальной UI-формулы не считается Core-реализацией.

Добавлен регрессионный тест полного пути KNOB + CONSTANT → ADD → FLOAT_OUTPUT, а также отрицательный тест на нечисловую константу. Результаты CI должны быть зафиксированы отдельно после завершения прогона; до этого DEV186 не объявляется принятым.


## 14. Изменения DEV187 — COMBINATION

В DEV187 добавлен сквозной Core-блок `COMBINATION`:

- четыре BOOL-входа `E/F/G/H`, один BOOL-выход `OUT`;
- четыре строки таблицы условий J/K/L/M;
- заглавная буква требует вход TRUE, строчная — FALSE, пустая ячейка игнорируется;
- условия внутри включённой строки объединяются AND, включённые строки объединяются OR;
- выключенные строки не участвуют; пустая включённая строка не создаёт TRUE;
- параметры строго проверяются при сохранении Core-графа и в compile-preview.

**Покрытие после DEV187:** 22 из 29 типов редактора имеют Core-контракт и путь компиляции. Остаются 7 неподдержанных сквозным путём типов: ANALOG_INPUT, EXTERNAL_SENSOR, PID_LOOP, DELAY, LATCH, SWITCH, TIME.

Добавлены тесты компиляции и Core execution по таблице истинности, а также отказа на неизвестной ячейке. До фактического завершения Windows CI DEV187 не считается принятым.


## 15. Изменения DEV188 — DELAY и LATCH

В DEV188 добавлены Core-контракты и исполняемая семантика двух stateful-блоков:

- `DELAY`: входы IN (BOOL) и TIME (FLOAT), выход OUT (BOOL); независимые on/off задержки, накопление времени по длительности реального FBD-тика, начальное состояние.
- `LATCH`: входы SET/RESET (BOOL), выход OUT (BOOL); удержание состояния и настраиваемый приоритет RESET/SET.

`FBDExecutionService` передаёт длительность тика в Core simulation, чтобы задержки не зависели от условной одной секунды при любом интервале. Состояние стратегии по-прежнему фиксируется только после успешного вычисления всего графа.

**Покрытие после DEV188:** 24 из 29 типов редактора имеют Core-контракт и путь компиляции. Остаются 5 неподдержанных сквозным путём типов: ANALOG_INPUT, EXTERNAL_SENSOR, PID_LOOP, SWITCH, TIME.

Добавлены тесты накопления on/off задержек, удержания LATCH, приоритета RESET и сквозной компиляции Studio → Core. До фактического завершения CI DEV188 не считается принятым.


## 16. Изменения DEV189 — ANALOG_INPUT и EXTERNAL_SENSOR

В DEV189 добавлены два числовых источника с безопасной табличной калибровкой:

- `ANALOG_INPUT`: виртуальный аналоговый источник с rawValue и необязательной характеристикой X/Y.
- `EXTERNAL_SENSOR`: виртуальный источник внешнего датчика с тем же явным контрактом калибровки.

При наличии scalingPoints Core выполняет кусочно-линейную интерполяцию с ограничением на крайние точки, как в редакторе. Таблица ограничена 20 точками; X/Y должны быть конечными числами, X уникальны. Если выбран Sensor Type, требуется минимум две точки. При отсутствии Sensor Type значение проходит без преобразования. Это инженерный/симуляционный источник, не драйвер и не чтение физического контроллера; реальные точки станции по-прежнему подключаются через POINT_INPUT.

**Покрытие после DEV189:** 26 из 29 типов редактора имеют Core-контракт и путь компиляции. Остаются PID_LOOP, SWITCH и TIME. Добавлены тесты компиляции, интерполяции и отказа на дублирующей X-координате. CI ещё должен подтвердить результат.


## 17. Изменения DEV190 — PID_LOOP

В DEV190 добавлен Core PID с четырьмя числовыми выходами OUT/P/I/D и шестью входами PV/SP/ENABLE/MANUAL/MANUAL_OUT/RESET. Реализованы:
- direct/reverse action;
- пропорциональная, интегральная и дифференциальная составляющие;
- derivative-on-measurement и фильтр D;
- deadband, output/integral limits, conditional-integration anti-windup;
- manual mode, tracking integrator и безударный возврат в AUTO;
- disabled output, reset и ограничение скорости выхода;
- фиксированный sampleTime и сохранение состояния в runtime_state стратегии.

Семантика перенесена из локального AVIC PID engine редактора в Core; это не утверждение о полной идентичности закрытому алгоритму Trend. Параметры проходят строгую серверную проверку. Компилятор сохраняет все четыре выхода, а Core simulator публикует значения по именам портов.

**Покрытие после DEV190:** 27 из 29 типов редактора имеют Core-контракт и путь компиляции. Остаются SWITCH и TIME. Добавлены тесты AUTO/MANUAL, bumpless transfer, RESET и сквозной Studio → Core compile/simulation. CI должен подтвердить результат.




## 18. Изменения DEV191 — SWITCH и TIME

DEV191 закрывает оставшиеся два типа редактора на уровне Core-контракта, компиляции и симуляции.

### SWITCH
- BOOL-вход IN является источником Status; если он не подключён, используется сохранённый bool-параметр Status.
- BOOL-выход OUT представляет Destination.
- Сохраняется PIN/user_level (0–99) как параметр доступа.
- Обратная связь запрещается общей проверкой циклов FBD.
- Симуляция и компиляция не выполняют физические записи.

Ограничение: PIN level сохраняется в модели, но отдельный операторский API изменения статуса с проверкой пользователя ещё не включён; изменение через инженерный редактор не следует считать runtime-командой.

### TIME
- Заменён ошибочный одиночный BOOL `OCC` на 21 выход Trend Time Module: Current Time (hh.mm), Minutes Past Midnight, Day, Month, Weekday, три day bits и 13 timing pulses.
- Пульсы фиксируются по переходу временного периода и удерживаются одну секунду.
- Время берётся из Core `TimeManagementService` и часового пояса станции; синхронизация/NTP и DST принадлежат Core Time Manager, а не скрытой логике FBD-блока.
- Time Master/запись системных часов из FBD не выполняются. Это намеренное безопасное отличие от контроллерной функции Trend Time Master.

**Покрытие после DEV191:** 29 из 29 типов редактора имеют Core-контракт, compile-preview, Core compile и simulation path. Это не означает полного совпадения всех внешних функций Trend: операторское управление SWITCH через RBAC и Time Master distribution остаются отдельными задачами.

Семантика сверена с Trend IQ3 Configuration Manual TE200768, Part 2 Section 31 (Switches) и Section 32 (Time): https://autorem.fr/Docs/Trend/iq3_config_EN.pdf
