# Лицензионный учёт привязок расписаний — DEV198

## Правило

Точка начинает занимать лицензионную ёмкость не при обнаружении устройства и не при простом наличии в каталоге, а при подключении к действующей инженерной функции. Для Scheduler такой функцией является сохранённая привязка выходной/двунаправленной точки к расписанию.

## Реализация

- ScheduleService принимает общий point_usage_service.
- При bind_point Scheduler передаёт полный актуальный набор точек расписания в CoreObjectService.set_point_usage с ключом schedule:<schedule_id>.
- Проверка лицензии выполняется до фиксации привязки в базе расписаний. Если лимит исчерпан, привязка не сохраняется.
- При unbind_point Scheduler передаёт оставшийся набор; если точка больше не используется никакой другой функцией, общий механизм снимает её активность.
- Общий учёт сохраняет уникальность: одна точка, используемая одновременно FBD, Graphics и Scheduler, занимает только один лицензионный слот.
- Подключение сделано в composition root CoreApplication.

## Границы и надёжность

Репозиторий объектов и БД Scheduler — отдельные SQLite-базы, поэтому это не единая SQLite-транзакция. Для привязки сначала выполняется лицензионная активация, затем запись Scheduler; при ошибке записи предусмотрена компенсация прежнего набора usage. Для снятия привязки запись Scheduler фиксируется первой, затем обновляется usage. Сбой второго шага может оставить временную лишнюю активную ссылку; это безопаснее, чем освободить слот при всё ещё действующей привязке, но требует последующей сверки.
