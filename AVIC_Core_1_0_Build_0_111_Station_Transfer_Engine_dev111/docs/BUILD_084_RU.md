# DEV84 — Общая навигация и внешние точки FBD

## Архитектурное решение

Общие разделы AVIC открываются через одну левую навигационную полосу. Контекстное содержимое остаётся специализированным: FBD показывает инженерное дерево станции и библиотеку блоков; Graphics — проект и библиотеку SVG; Web Pages — дерево страниц и редактор. Это разделяет глобальную навигацию и рабочие инструменты, не смешивая команды разных редакторов.

## Привязка физической точки

Внешняя точка оборудования остаётся объектом Point в AVIC Core. FBD-модуль хранит ссылку `pointRef` и контракт `externalPointBinding`:

- `pointId` — внутренний идентификатор AVIC Point;
- `protocol` — протокол источника, например `bacnet/ip` или `modbus/tcp`;
- `deviceId`, `deviceName`, `deviceAddress` — идентичность устройства;
- `nativeIdentity` — исходный адрес объекта/регистра в протоколе;
- `objectType`, `dataType`, `direction`, `unit` — типизированные свойства;
- `readOnly=true` — в DEV84 нет права отправки команд из этой привязки.

FBD не интерпретирует BACnet Object Identifier или Modbus register. Он получает нормализованные метаданные и значение из Core. Добавление одной точки на схему не создаёт новую физическую точку и не должно увеличивать лицензионный счётчик повторно: лицензирование остаётся привязано к исходному Point UID.

## Точность

`displayPrecision` управляет только текстовым представлением. По умолчанию — 2 десятичных знака. Значения в Point Registry, арифметике и будущей записи не должны округляться форматтером интерфейса.

## Следующий этап

1. Единый Live Point Engine с подписками/обновлением качества и временных меток.
2. Драйверные адаптеры BACnet и Modbus, единый цикл чтения и контролируемый write path.
3. FBD Runtime, потребляющий Point Registry, а не локальные снимки `params.value`.
4. Command Manager с правами, приоритетами, interlock, read-back и аудитом.
5. BACnet Server для публикации точек AVIC наружу.
6. Выделение общего Engineering Tree в единый переиспользуемый компонент интерфейса.
