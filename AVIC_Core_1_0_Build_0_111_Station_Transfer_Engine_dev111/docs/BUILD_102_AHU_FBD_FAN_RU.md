# DEV102 · Приёмочный сценарий ПВУ / FBD / анимация

## Цель

Проверить, что AVIC может отобразить модульную приточную установку, прочитать точку через Core Point Runtime, вычислить BOOL-разрешение в FBD и использовать его для анимации ротора вентилятора.

## Состав мнемосхемы

`create_modular_ahu_demo()` создаёт 7 секций в одной горизонтальной линии:

1. Наружная воздушная заслонка.
2. Фильтры G4/F7.
3. Пластинчатый рекуператор.
4. Водяной нагреватель.
5. Водяной охладитель.
6. Приточный вентилятор.
7. Выходной короб.

Символы — встроенные AVIC SVG. Секция вентилятора содержит `.fan-rotor`, CSS keyframes `avicFanSpin` и режим движения воздуха.

## Сквозная логика

- В FBD добавляется `POINT_INPUT`, связанный с реальной точкой станции по Core UUID.
- `POINT_INPUT` читает Core Point Runtime; значение не берётся из отображаемого имени или адреса.
- Точка и FBD должны принадлежать одной станции.
- BOOL-сигнал проходит через FBD (в тесте — `AND` с отдельным разрешающим входом).
- Выход FBD связывается с элементом `ahu_section_supply_fan`.
- Graphics Workbench периодически получает read-only результат FBD evaluation.

## Ожидаемое поведение

| Состояние результата FBD | Состояние ротора |
|---|---|
| GOOD / TRUE | Вращается |
| GOOD / FALSE | Остановлен |
| BAD / UNCERTAIN / STALE / ошибка расчёта | Остановлен (fail-safe) |

CSS animation duration: `0.72s`, linear, infinite. При обновлении данных каждые 1,5 секунды время анимации сохраняется, ротор не начинает вращение заново.

## Ограничения

FBD evaluation в DEV102 возвращает `SIMULATION_ONLY`, `runtime_published=False`, `field_writes_performed=False`. Это инженерный preview, а не загруженная в контроллер стратегия и не команда пуска. Для реального пуска требуется отдельная проверка FBD runtime, Command Manager, прав доступа, обратной связи и полевого контроллера.
