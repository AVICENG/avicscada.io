# Driver Manager DEV57 — инвентаризация и безопасное создание экземпляров

## Что реализовано
- Каталог встроенных профилей BACnet/IP, Modbus TCP и необязательного Trend IQ3.
- Просмотр каталога через `GET /api/drivers/catalog`.
- Создание и хранение экземпляра драйвера в конкретной станции: `POST /api/stations/{station_id}/drivers`.
- Просмотр списка: `GET /api/stations/{station_id}/drivers`; карточка: `GET /api/driver-instances/{instance_id}`.
- Экземпляр создаётся только в состоянии `STOPPED`, `enabled=false`; полевая связь и запуск не включаются.
- Проверяется принадлежность станции и наличие драйвера в доверенном встроенном каталоге.
- Секреты запрещено помещать в обычный config; для них предназначен SecretStore.
- Мутации API проходят локальный Origin/loopback guard.

## Как проверить через HTTP
1. Откройте `GET /api/drivers/catalog` и выберите `driver_id`.
2. Создайте экземпляр POST-запросом на `/api/stations/{station_id}/drivers` с JSON `{"driver_id":"bacnet-ip","name":"BACnet LAN","config":{"interface_id":"eth0"}}`.
3. Убедитесь, что ответ содержит `state=STOPPED`, `enabled=false`, `field_io_enabled=false`.
4. Откройте список экземпляров станции и убедитесь, что запись сохраняется.

## Ограничения
Это пока не полноценный пакетный менеджер и не исполняемый драйверный runtime. Нет установки сторонних пакетов, проверки цифровой подписи модулей, dependency resolver, конфигурационных схем драйверов, polling/subscriptions, активного discovery, reconnect и команд записи. Trend оставлен необязательным профилем. TONN не реализован: для будущих Linux-контроллеров AVIC предусмотрено направление отдельного адаптера/протокола, но текущий код не заявляет совместимость с TONN.


## DEV124 — runtime lifecycle Driver Manager

- DriverManagerService теперь владеет зарегистрированными adapter factories, PollingSession, стартом/остановкой и диагностикой экземпляров.
- Встроены безопасные фабрики BACnet/IP и Modbus TCP: создание клиента и адаптера выполняется только при явном start_instance; конфигурация валидируется, binding создаётся из явно заданного списка.
- Состояния экземпляра персистентны: STARTING/RUNNING/ERROR/STOPPED; optimistic version check при изменениях. CoreApplication останавливает активные драйверы при shutdown.
- UI использует единственный CoreApplication.driver_manager, а не создаёт отдельный менеджер с независимым состоянием.
- MQTT остаётся подписочным адаптером; его Paho factory пока должна быть зарегистрирована отдельным runtime-пакетом с TLS/SecretStore wiring. Каталог показывает runtime_start_supported отдельно от read_supported.
- Вложенные секреты запрещены рекурсивно.
- Добавлены тесты lifecycle/factory, persisted state, close и secret rejection.
- Это первый runtime lifecycle слой, не финальный промышленный Driver Manager: пока нет recovery после аварийного завершения процесса, лицензирования пакетов, heartbeat/watchdog и UI настройки параметров.


## DEV125 — корректное закрытие BACnet транспорта

- Добавлен close() у BACnet/IP Point Adapter: остановка Driver Manager освобождает UDP socket клиента.
- Исправлена защита register_adapter_factory: factory нельзя менять, пока существует активная polling session.
- Modbus TCP не держит постоянный socket: каждая транзакция открывает и закрывает ограниченное соединение.


## DEV126 — lifecycle failure rollback and shutdown test

- Если запуск polling worker/персистентного состояния завершается ошибкой, Driver Manager пытается остановить созданную сессию, закрыть транспорт и удалить временные ссылки до фиксации ERROR.
- Уточнён тест: BACnet/IP и Modbus TCP имеют встроенные runtime factories, поэтому start_supported=true; это не означает разрешение записи.
- Добавлен тест, подтверждающий, что CoreApplication.close останавливает активную сессию драйвера, закрывает адаптер и сохраняет STOPPED.


## DEV127 — уточнение теста инварианта состояния

- Тест создания DriverInstance с enabled=True при состоянии STOPPED теперь проверяет фактическую ошибку согласованности enabled/state.
- Runtime DriverInstance может быть восстановлен из хранилища в RUNNING/DEGRADED, поэтому сообщение об ошибке отражает несоответствие состояния, а не запрещает активные сохранённые состояния.


## DEV128 — аудит жизненного цикла и достоверности состояния

- Каталог MQTT переведён в PLANNED: подписочный адаптер существует, но production factory, безопасная SecretStore интеграция и подтверждённая TLS-конфигурация ещё не завершены.
- Диагностика различает эффективное состояние polling worker и состояние, сохранённое в БД. Если после перезапуска процесса в БД остался RUNNING, но worker отсутствует, состояние показывается как ORPHANED.
- Карточка экземпляра сообщает field_read_enabled отдельно от field_write_enabled; запись остаётся отключённой.
- CoreApplication.stop_station останавливает драйверы этой станции до завершения Station Runtime. При ошибке остановки драйвера остановка Station Runtime всё равно предпринимается, а вызывающая сторона получает явную ошибку.
- Добавлены регрессионные тесты на DEGRADED, ORPHANED и остановку драйверов вместе со станцией.
- Полный перечень замечаний, ограничений и источников: docs/DRIVER_AUDIT_DEV128_RU.md.

## DEV131 — групповое чтение Modbus TCP

- Смежные/перекрывающиеся bindings одного function code объединяются в один запрос в пределах нормативных лимитов.
- FC01/02 ограничены 2000 битами, FC03/04 — 125 регистрами на запрос.
- Каждая точка декодируется независимо из общего ответа; ошибка группы помечает все затронутые точки BAD_COMMUNICATION.
- Добавлен тест сокращения двух чтений соседних регистров до одного запроса.


## DEV132 — BACnet/IP socket serialization

- Сериализованы операции discovery/read_property на одном BACnet client, включая Invoke ID и общий UDP receive socket.
- ReadProperty проверяет полный source endpoint (IP и UDP port).
- Сегментированный ComplexACK явно диагностируется как неподдерживаемый; поддержка сегментации не заявляется.


## DEV133 — исправления жизненного цикла

- DriverManager.stop_station поддерживает runtime station до создания инженерной inventory-записи.
- Замена factory блокируется только для соответствующего активного протокола.
- Проверка секретов нормализует имена полей и блокирует распространённые aliases.


## DEV135 — достоверное состояние в списке

- PollingSession.start возвращается после подтверждения RUNNING worker.
- Список экземпляров показывает фактический state и отдельный persisted_state; DEGRADED/ORPHANED не маскируются сохранённым RUNNING.
- Фильтр секретов блокирует дополнительные распространённые aliases.
