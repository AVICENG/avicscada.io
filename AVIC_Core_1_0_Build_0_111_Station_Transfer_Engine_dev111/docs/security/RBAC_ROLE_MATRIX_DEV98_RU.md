# AVIC RBAC — шаблоны ролей DEV98

## Базовый принцип

Пароль подтверждает личность и не задаёт полномочия. Полномочия определяются назначенными ролями и отдельными grants на область ресурса. Сессия создаётся после аутентификации; MFA и повторная аутентификация усиливают подтверждение личности, но не заменяют RBAC.

Роль без scope-grant не даёт доступ к станции. Для станционных операций `AuthorizationService` требует одновременно permission ID и station scope.

## Новые шаблоны

| Роль | Основные полномочия |
|---|---|
| `avic_viewer` | Чтение проекта/станции/точек/мнемосхем/аварий/трендов/событий |
| `avic_operator` | Чтение, подтверждение аварий, команды start/stop в разрешённой области |
| `avic_senior_operator` | Операторские права + изменение уставок, расписаний и ручной режим |
| `avic_engineer` | Инженерная конфигурация, привязки, публикация графики, FBD, настройка драйверов и Discovery |
| `avic_security_admin` | Пользователи, назначение ролей, аудит и безопасность; без инженерного deploy по умолчанию |

Существующие `viewer`, `operator`, `engineer`, `project_administrator`, `customer_administrator` и `system_administrator` сохранены для обратной совместимости. Новые `avic_*` шаблоны дают более гранулярную модель и не изменяют старые профили.

## Матрица прав

| Действие | Viewer | Operator | Senior Operator | Engineer | Security Admin |
|---|:---:|:---:|:---:|:---:|:---:|
| Просмотр мнемосхем | ✓ | ✓ | ✓ | ✓ | ✓ |
| Подтверждение аварий | — | ✓ | ✓ | ✓ | — |
| Запуск/остановка | — | ✓ | ✓ | —* | — |
| Изменение уставок | — | — | ✓ | —* | — |
| Ручной режим | — | — | ✓ | —* | — |
| Изменение расписаний | — | — | ✓ | ✓ | — |
| Изменение мнемосхем | — | — | — | ✓ | — |
| Изменение привязок | — | — | — | ✓ | — |
| Публикация мнемосхем | — | — | — | ✓ | — |
| FBD/logic edit & deploy | — | — | — | ✓ | — |
| Пользователи и роли | — | — | — | — | ✓ |
| Настройка безопасности | — | — | — | — | ✓ |

`—*` означает: инженерский шаблон не получает операторские команды автоматически. При необходимости это отдельное явное назначение `equipment.command.start/stop` или `setpoint.write` в конкретной области.

## Ключевые permission ID

`graphics.read`, `graphics.configure`, `graphics.binding.configure`, `graphics.publish`, `equipment.command.start`, `equipment.command.stop`, `equipment.manual_mode`, `setpoint.write`, `alarm.acknowledge`, `schedule.configure`, `logic.edit`, `logic.deploy`, `user.manage`, `role.assign`, `security.configure`.

## Обязательные правила production-интеграции

1. API проверяет permission и station/project scope на сервере для каждого запроса.
2. Скрытие кнопки в UI не считается защитой.
3. Мнемосхема не получает права записи от наличия read-binding.
4. Команда проверяется отдельно от чтения и обратной связи.
5. Операции записи требуют CSRF-защиты, аудита, проверки блокировок/межблокировок; для критичных действий — MFA/step-up.
6. Временный Access Lease ограничивает срок права управления; после истечения право не продлевается молча.
7. Роли не заменяют область действия: доступ к одной станции не означает доступ ко всем станциям.
