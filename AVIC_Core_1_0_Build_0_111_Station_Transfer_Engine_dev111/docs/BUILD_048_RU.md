# AVIC Core 1.0 — DEV48: Scheduler Editor Operations

## Цель сборки
Развить Scheduler Manager DEV47 из списка интервалов в более наглядное инженерное рабочее место и добавить безопасные массовые операции с недельным расписанием.

## Реализовано
- 24-часовая недельная обзорная сетка: 7 дней, временная шкала 00:00–24:00, визуальное положение и длительность событий.
- Сохранён подробный список недельных событий с точным временем, значением и удалением.
- Добавлена операция `POST /api/schedules/{schedule_id}/weekly-days/copy`.
- Copy Day: копирование интервалов выбранного дня в указанные дни.
- Apply M-F: применение выбранного дня к рабочим дням (без изменения исходного дня).
- Copy to remaining days: копирование выбранного дня на все остальные дни недели.
- Операция выполняется одной SQLite-транзакцией: целевые дни заменяются целиком, исходный день остаётся без изменений.
- Проверяется диапазон дней, дубликаты, запрет включения исходного дня и optimistic revision.
- Действие фиксируется в AuditService (`schedule.weekly_day.copied`) с source/target и числом скопированных событий.
- Добавлены unit/API тесты успешного копирования, очистки назначения при пустом источнике, некорректных дней, конфликта ревизий и API маршрута.

## Граница безопасности
Scheduler по-прежнему вычисляет schedule intent. Он не пишет в Point и не отправляет команды BACnet/Modbus. Копирование дней изменяет только конфигурацию расписания. Физическое управление требует отдельного Command Manager с приоритетами, interlock, lease, approval, read-back и fail-safe.

## Ограничения DEV48
- Сетка пока обзорная: drag/resize интервалов мышью ещё не реализованы.
- Нет редактирования существующего интервала на сетке; добавление и удаление выполняются через формы/список.
- Нет ежегодных/повторяющихся календарных правил, отдельных Calendar объектов, Schedule Selector и Trigger Schedule.
- Нет циклического фонового runtime и доставки расписания в контроллер.
- Не выполнена браузерная приёмка на Windows в пользовательской среде.
- Текущая авторизация UI использует локальный операторский guard; это не следует считать завершённой многоуровневой RBAC-приёмкой.

## Статус
**Scheduler Manager стал удобнее для инженерного редактирования недельной конфигурации, но не является законченным промышленным Scheduler.** Следующий этап — pointer-based drag/resize с сохранением через optimistic revision, календарные правила и отдельный Scheduler Runtime. До появления Command Manager физические команды запрещены.
