# Web Application Page Builder — DEV107

## Назначение

Page Builder создаёт операторские страницы станции в ветке Repository → Web Application. Данные страниц хранятся в Core Repository как `WebPageNode`; графические документы, точки и ресурсы остаются собственностью соответствующих Core-сервисов. Repository не создаёт дубликаты Point Runtime или Graphics.

## Навигация

- Общий узел «Репозиторий» станции открывает `/repository?station=<station-id>&section=WebApplication`.
- Узел Web Application и конкретные узлы сайта/папки/страницы открывают тот же редактор; при выборе страницы она загружается в редактор.
- Узлы Graphics открывают отдельный Graphics Workbench. Старый `pages.html` не используется.

## Создание страницы

1. Выберите станцию.
2. Откройте Repository → Web Application.
3. Нажмите «Сайт» и задайте имя.
4. Выберите сайт и нажмите «Страница»; при необходимости сначала создайте папку.
5. Выберите созданную страницу в дереве.

## Компоновка

Палитра содержит заголовок, текстовую надпись, изображение, значение точки, мнемосхему, разделитель, карточку и декоративную кнопку. Элемент можно добавить нажатием по палитре или перетаскиванием на холст. Геометрия редактируется в свойствах X/Y/ширина/высота.

Для значения точки выбирается стабильный ID физической или виртуальной Core-точки. При сохранении проверяется существование точки и её принадлежность той же станции. Качество не-GOOD отображается как состояние качества, а не как нормальное значение.

Изображения загружаются в Repository Assets станции. Разрешены PNG/JPEG/GIF/WebP, до 3 МБ, с проверкой сигнатуры файла. Мнемосхема должна быть назначена странице; при публикации её конфигурация фиксируется в snapshot, а значения привязок остаются read-only live из Point Runtime.

## Сохранение и публикация

- Сохранение использует `expected_revision` и optimistic concurrency.
- Публикация проверяет layout, point bindings и назначенные Graphics документы.
- Снимок публикации неизменяем относительно последующих правок исходной мнемосхемы.
- История публикаций хранит до 50 версий; доступны unpublish и rollback через API.
- Публичный маршрут имеет вид `/published/<station-id>/<page-path>`.
- Live значения на опубликованной странице обновляются через read-only Point Runtime polling.

## Ограничения

- Кнопка в Page Builder пока декоративная и не отправляет команды.
- Command Manager DEV106 не интегрирован в операторскую страницу и остаётся SIMULATION_ONLY.
- Нет customer-grade login/session, server-side RBAC и MFA; изменяющие операции защищены loopback-only development guard.
- Предпросмотр редактора не заменяет браузерное acceptance-тестирование опубликованной страницы.
- Нет customer-grade reverse-proxy/HTTPS deployment profile.

## Приёмочный маршрут

Создать проект и станцию → открыть Repository из общего дерева → создать сайт и страницу → добавить заголовок, надпись, изображение, точку и мнемосхему → сохранить → опубликовать → открыть URL → проверить read-only обновление значений и неизменность snapshot Graphics после изменения исходного документа.

## DEV155 — публикация непосредственно из Page Builder

- В верхней панели редактора доступны действия «Опубликовать» / «Опубликовать новую версию», «Открыть публикацию» и «Снять с публикации».
- Перед публикацией редактор сохраняет текущий черновик; если сохранение не удалось, публикация не запускается.
- Статус показывает, опубликована ли страница, и номер опубликованной версии. Для открытия используется URL, возвращённый Core Web Pages Service.
- Снятие с публикации требует подтверждения; история опубликованных версий сохраняется на стороне Core и может быть использована API отката.
- Визуальный выбор версии для rollback остаётся следующим шагом; API отката уже существует.


## DEV157 — история снимков и визуальный откат публикации

- История каждой публикации хранит полный замороженный layout, включая snapshots назначенных мнемосхем и конфигурацию bindings.
- Откат восстанавливает сохранённый снимок публикации, а не текущую рабочую графику; текущий черновик страницы не перезаписывается.
- В Page Builder добавлены выбор опубликованной версии и команда отката с подтверждением.
- Сквозной тест изменяет исходную графику после публикации, проверяет неизменность опубликованной геометрии и bindings, затем выполняет откат к первой версии.
- Исторические версии, созданные до DEV157, могут не содержать frozen graphic snapshots; их безопасный откат требует отдельной проверки.


## DEV158 — совместимость отката и проверка после перезапуска

- Исторические записи, содержащие графические блоки без frozen graphic snapshot, теперь отклоняются при rollback с явной диагностикой; повреждённая или неполная публикация не активируется.
- Сквозной тест после перезапуска отдельно проверяет редактируемый источник графики и неизменённые bindings опубликованного снимка.
- Добавлены UI regression assertions для выбора версии и команды rollback.

## DEV195 — завершение привязки точек и публикационного сценария

- В инспекторе визуального Page Builder добавлен выбор Core-точки для компонента «Значение»; поддержано и перетаскивание физической/FBD-точки из инженерного дерева прямо на виджет значения.
- Каталог загружается из общего API инженерных точек в контексте выбранной станции; включает физические точки и виртуальные FBDExposedPoint.
- В списке отображаются имя, устройство/протокол, последнее доступное значение, единица и качество. В страницу сохраняется стабильный Core point ID, а не копия значения.
- Сохранение и публикация повторно проверяют существование точки и принадлежность той же станции. Не-GOOD качество не маскируется как нормальное значение: опубликованная страница показывает состояние качества.
- Компонент «Кнопка / ссылка» теперь публикуется как HTML-ссылка, если задан href. URL проходит серверную проверку и HTML-экранирование; без href компонент остаётся текстовой кнопкой без действия.
- Публикация сохраняет immutable snapshot layout и мнемосхем; live point values остаются read-only и читаются из Point Runtime. Доступны версии, снятие с публикации и откат.
- Пользовательский JavaScript остаётся только в sandbox preview; он не исполняется на опубликованной странице. Публикуемый путь — визуальные компоненты и проверенные привязки.

**Ограничения, которые не следует считать закрытыми:** customer-grade authentication/RBAC/MFA, HTTPS/reverse-proxy deployment profile, удалённая активация пакетов, операторские команды через Command Manager и публикация произвольного HTML/JS. Эти функции не включаются в текущий безопасный визуальный publish scope.
