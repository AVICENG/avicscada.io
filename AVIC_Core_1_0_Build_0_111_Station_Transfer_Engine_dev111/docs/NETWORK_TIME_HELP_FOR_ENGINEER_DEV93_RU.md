# Сети и время AVIC — руководство простым языком (DEV93)

## Назначение

Интерфейс должен помогать инженеру, который не является сетевым администратором. Он объясняет, что означает каждый параметр, зачем он нужен, где его взять и что произойдёт после нажатия кнопки. Неизвестные сетевые параметры нельзя угадывать.

## Рекомендуемый маршрут подключения

1. Создать проект и станцию для конкретного объекта.
2. В дереве выбрать станцию и создать физическую сеть.
3. Выбрать режим:
   - **Автоматически** — использовать реальный сетевой адаптер компьютера, на котором сейчас запущен AVIC.
   - **Вручную** — записать план IP-адреса будущего компьютера диспетчеризации. Этот режим подходит для проектирования до установки на объекте.
4. Добавить протокольный канал: например, BACnet/IP или Modbus TCP.
5. Добавить устройство по известному адресу либо выполнить разрешённое обнаружение.
6. Проверить сначала IP-доступность, затем доступность нужного порта, затем обмен через драйвер.
7. Импортировать точки и продолжить инженерную работу.

## Сетевые термины

- **IP-адрес** — адрес устройства в IP-сети, например `192.168.10.70`.
- **Подсеть** — группа адресов, которые считаются одной локальной сетью. Запись `192.168.10.0/24` — краткая запись адреса сети и маски.
- **Шлюз / маршрутизатор** — устройство, через которое пакеты уходят из одной сети в другую. Часто это адрес вроде `192.168.10.1`.
- **Шлюз протоколов** — промышленное устройство, которое может переводить данные между разными протоколами. Это не то же самое, что IP-маршрутизатор.
- **DNS** — служба, которая сопоставляет понятные имена компьютеров с IP-адресами.
- **Порт** — номер сетевой службы на устройстве. Для Modbus TCP стандартно часто используется TCP 502.
- **Ping** — проверка, отвечает ли IP-адрес на ICMP Echo. Отсутствие ответа не доказывает, что устройство выключено: Ping может быть запрещён.
- **Маршрут** — путь, по которому компьютер достигает другой IP-сети.
- **NTP** — служба сверки системных часов с источником точного времени.

## Разные подсети

Устройство не обязано находиться в той же подсети, что и AVIC. Связь между подсетями возможна, если на объекте настроена маршрутизация и правила доступа. AVIC не должен автоматически менять IP устройства, маршрутизатор, DHCP, VLAN, NAT или правила межсетевого экрана.

Для BACnet/IP широковещательное обнаружение обычно ограничено локальным сегментом. Для связи через маршрутизируемые сети может понадобиться BBMD или регистрация Foreign Device. Сам факт доступности IP не гарантирует доступность BACnet.

## Время на распределённых объектах

Каждая станция имеет собственный часовой пояс по месту расположения объекта. Например:

- Москва: `Europe/Moscow`.
- Владивосток: `Asia/Vladivostok`.

В AVIC следует различать:

- **UTC** — единая шкала времени для журналов, архивов, тревог и обмена между станциями.
- **Местное время объекта** — время, по которому выполняются недельные расписания и которое удобно оператору на площадке.
- **Монотонные часы** — источник для длительностей, таймаутов и циклов Runtime; не зависит от перевода системных часов.

В расписании хранится календарное правило местного времени объекта, а не только постоянный сдвиг UTC. Часовой пояс задаётся идентификатором IANA, чтобы учитывать изменения правил часовых поясов.

## Важные ограничения DEV93

- Интерфейс Time Manager позволяет выбрать станцию, часовой пояс, сохранить политику NTP и посмотреть вычисленное UTC/местное время.
- Сохранение политики NTP в Core само по себе не перенастраивает Windows Time Service и не подтверждает реальную синхронизацию с NTP-сервером.
- Разрешение синхронизации времени отдельного контроллера сохраняется отдельно, с указанием согласовавшего и причины. Фактическая передача времени в контроллеры в этой сборке не выполняется.
- Настройка сетевого плана не меняет IP компьютера или полевых устройств.
- DEV93 улучшает русскоязычные подсказки и рабочий интерфейс. Это не является завершённой реализацией межстанционного протокола или Supervisor.

## Связь расписания с Time Manager

При создании нового расписания Workbench автоматически читает часовой пояс выбранной станции из Time Manager. Инженеру не нужно повторно вводить `Europe/Moscow` или `Asia/Vladivostok` вручную. Часовой пояс показывается в поле только для чтения. Если на станции ещё не задано местное время, Core возвращает UTC как исходное значение; перед созданием рабочих расписаний инженер должен выбрать правильный часовой пояс объекта в разделе «Время и синхронизация».
