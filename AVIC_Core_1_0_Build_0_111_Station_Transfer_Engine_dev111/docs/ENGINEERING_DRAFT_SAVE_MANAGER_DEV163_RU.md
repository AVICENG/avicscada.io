# Engineering Draft / Save Manager — DEV163 / DEV164

## Назначение

Общий механизм черновиков для инженерных редакторов. Черновик, сохранённая рабочая конфигурация и опубликованная/применённая конфигурация — разные состояния.

## Подключённые редакторы

- **FBD Studio** — дополнительная страховочная копия в Save Manager; существующее сохранение FBD в Core остаётся рабочим механизмом. Переключение FBD-проекта больше не должно ожидать завершения сетевой записи предыдущего проекта: снимок старого проекта ставится в очередь с захваченным ID и ревизией.
- **Graphics Workbench** — автоматический черновик элементов и восстановление; явная кнопка «Сохранить» по-прежнему записывает основную мнемосхему.
- **Repository / Web Application** — автоматический черновик имени, slug и layout; явная кнопка «Сохранить» записывает страницу. Публикация остаётся отдельным действием.

## Правила работы

1. Переход между разделами и документами не блокируется ожиданием сетевого сохранения.
2. При изменении редактор делает локальную копию в IndexedDB (короткая задержка), затем отправляет черновик в Core.
3. Если Core недоступен, локальная копия остаётся на этом браузерном профиле; при следующем открытии редактор предлагает восстановить найденный черновик.
4. Если одновременно есть локальная и серверная копии, для предложения восстановления выбирается более новая по времени.
5. Серверные записи версионируются через compare-and-swap (expected_draft_revision). При конфликте более новая запись не перезаписывается; локальная копия сохраняется.
6. В черновике отдельно хранятся base_revision исходного объекта и draft_revision.
7. Черновик не публикуется, не запускается и не применяется автоматически.
8. При успешном основном сохранении редактор удаляет соответствующий черновик по его ревизии.

## API

- GET /api/stations/{station_id}/engineering-drafts — список черновиков станции.
- GET /api/engineering-drafts/{editor}/{station_id}/{resource_id} — получить черновик.
- PUT /api/engineering-drafts/{editor}/{station_id}/{resource_id} — записать новую ревизию черновика.
- DELETE /api/engineering-drafts/{editor}/{station_id}/{resource_id}?expected_draft_revision=N — удалить конкретную ревизию.

Допустимые editor: fbd, graphics, web-page. PUT body: base_revision, expected_draft_revision, content.

## Хранение и безопасность

Сервер: SQLite databases/engineering_drafts.sqlite3, WAL, транзакция BEGIN IMMEDIATE. Размер одного серверного черновика ограничен 5 MiB; содержимое должно быть конечным JSON-объектом. Изменяющие API требуют локального оператора и проходят существующую проверку Origin. Клиентская копия хранится в IndexedDB в профиле браузера.

## Ограничения и дальнейшие проверки

- Browser automation / end-to-end сценарии аварийного закрытия браузера пока не подтверждены CI. pagehide используется только как best effort; браузер не гарантирует завершение асинхронных запросов при закрытии. Надёжность обеспечивается регулярной записью в IndexedDB, а не beforeunload.
- UI сравнения/слияния конфликтующих черновиков пока нет: при конфликте система сохраняет локальную копию и сообщает инженеру о конфликте.
- IndexedDB привязана к профилю и origin браузера; очистка данных браузера может удалить локальную копию. Серверная копия независима.
- Интеграция с полноценной пользовательской RBAC/многопользовательской идентичностью будет завершена вместе с общей системой сессий и прав.
- Проверены серверное хранилище и API unit/API tests; сквозные браузерные сценарии должны пройти отдельную автоматизацию до объявления функции полностью принятой.


## Дополнительная защита DEV166

- Чтение черновиков (получение одного черновика и списка станции) теперь также проходит через локальную проверку оператора и Origin. Cross-origin запросы с постороннего сайта отклоняются.
- Перед первой серверной записью клиент дожидается завершения первоначального поиска черновика и получения его ревизии. Это устраняет гонку, когда быстрое редактирование могло отправить expected revision 0 до чтения существующего черновика.
- Удаление черновика после основного сохранения теперь условное: содержимое черновика должно совпадать с тем, что только что сохранено. Если во время сохранения появились более новые правки или найден другой черновик из другой вкладки, черновик сохраняется, а UI сообщает об этом.
- Серверная копия удаляется до локальной. При сетевой ошибке или конфликте удаления локальная страховочная копия не удаляется и интерфейс не сообщает ложное «всё сохранено».
- Основное сохранение Graphics/Web Application и FBD больше не должно затирать правки, внесённые параллельно с запросом сохранения: ревизия основной конфигурации обновляется, а оставшиеся изменения сохраняются как черновик.

## Проверки DEV166

Добавлен API-тест, который подтверждает блокировку чтения черновика с недоверенным Origin и разрешение локального Origin. Статические проверки Save Manager дополнены проверками ожидания recovery и защиты от удаления другого черновика.

- Если редактор обнаружил черновик при открытии, серверная синхронизация новых правок приостанавливается до явного решения инженера. Новые изменения продолжают сохраняться локально; существующий серверный черновик не перезаписывается.
- Найденная локальная копия перед новыми записями переносится в отдельный ключ IndexedDB `*:recovery`. Это позволяет не затирать найденную копию новыми правками, пока инженер выбирает восстановление или отклонение.
- При основном сохранении проверяется не только текущая форма редактора, но и содержимое серверной и локальной копий. Отличающийся черновик из другой вкладки не удаляется.
- Перед удалением черновика после основного сохранения клиент дожидается завершения уже начатой транзакции IndexedDB. Это исключает гонку, при которой поздно завершившаяся локальная запись могла бы воскресить уже очищенный черновик.
- Снимок содержимого и базовая ревизия фиксируются в момент вызова flush, а не после сетевого ожидания. Если пользователь переключает документ, пока предыдущая запись ещё выполняется, отложенная запись использует сохранённые ID документа, снимок и base_revision прежнего редактора, а не состояние уже открытого нового документа.
- Дополнительно проверены точки изменения Graphics Workbench: удаление клавишей Delete/Backspace, привязка выхода FBD к вентилятору, добавление изображения из библиотеки и загрузка изображения в Repository запускают сохранение черновика после завершения изменения модели.
- При принудительном flush (включая pagehide) локальный снимок IndexedDB записывается до ожидания сетевой проверки существующего серверного черновика. Поэтому временная недоступность Core не задерживает начало локального сохранения.
- Добавлена необязательная проверка синтаксиса Save Manager через `node --check`, если Node.js установлен в тестовой среде.


## DEV167 — выход из AVIC и закрытие окна

### Штатный выход из приложения

- В общую навигационную панель всех рабочих пространств добавлена команда **«Выход из AVIC»**.
- Команда открывает собственное окно подтверждения, вызывает Save Manager и ждёт подтверждения сохранения последних изменений.
- Если черновик записан в Core, инженер получает подтверждение синхронизации.
- Если Core недоступен, но точная последняя редакция записана в IndexedDB, выход разрешается с явным сообщением, что черновик сохранён локально и будет доступен в этом профиле браузера.
- Если не удалось подтвердить ни локальную, ни серверную копию, предлагается повторить сохранение, остаться в AVIC либо явно подтвердить выход с риском потери последних изменений.
- Штатный выход не публикует страницу, не запускает FBD и не применяет конфигурацию к оборудованию.

### Закрытие вкладки / окна браузера

- Для закрытия через крестик браузера, Alt+F4 и аналогичных действий используется стандартное событие beforeunload.
- Браузер показывает собственное системное предупреждение только если есть изменения, для которых ещё не подтверждена ни локальная, ни серверная страховочная копия.
- Текст системного предупреждения контролирует браузер; AVIC не может подменить его собственным диалогом или гарантированно остановить закрытие.
- Если локальная копия последних изменений уже подтверждена в IndexedDB, закрытие не блокируется, даже если Core временно недоступен.
- pagehide остаётся резервной попыткой, а не гарантией сохранения. Поэтому основной механизм — регулярная запись черновика во время редактирования и явная подготовка к выходу через команду AVIC.

### Граница платформы

Текущий AVIC Workbench работает как веб-приложение в браузере. Страница не может перехватить системное закрытие браузера и показать полностью собственный диалог, а также не может программно закрыть вкладку, которую пользователь открыл вручную. После успешной подготовки к выходу браузер может потребовать закрыть вкладку стандартной кнопкой. Для полноценного перехвата нативного события закрытия окна и управления окном потребуется отдельная Desktop-оболочка.

### Новые проверки

- Проверка отдачи lifecycle JavaScript и наличия команды выхода на главной странице, Graphics, FBD и Repository.
- Проверка, что Save Manager загружается только в редакторах, а общий обработчик закрытия присутствует во всех рабочих пространствах.
- Синтаксическая проверка lifecycle JavaScript через Node.js, если он установлен в CI.
- Полноценные испытания закрытия вкладки в реальном браузере остаются отдельным E2E этапом и не объявляются пройденными только на основании API-тестов.
- Снимки для отложенной локальной записи, сетевого flush и подготовки к выходу теперь глубоко копируются через JSON-сериализацию в момент захвата. Последующее редактирование объекта в памяти не может изменить уже поставленный в очередь снимок.
- На главной странице, где нет активного редактора, диалог выхода сообщает об отсутствии открытых редакторов, а не заявляет, что несуществующий черновик был сохранён.
- Подготовка к выходу не ждёт завершения сетевого поиска старого черновика до локальной записи: сначала фиксируется точный локальный снимок, затем ограниченное время ожидается синхронизация с Core. При недоступности Core локальная копия может подтвердить безопасный выход.
