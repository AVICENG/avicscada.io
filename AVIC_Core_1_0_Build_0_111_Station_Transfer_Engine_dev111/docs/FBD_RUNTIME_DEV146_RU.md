# DEV146 — Масштабирование циклического FBD Runtime

## Реализовано

- Вместо отдельного daemon-потока для каждой стратегии используется один общий scheduler thread.
- Вычисления выполняются ограниченным ThreadPoolExecutor (по умолчанию 4 рабочих потока; допустимо 1–64).
- Каждая стратегия имеет флаг in-flight: второй цикл не ставится в очередь, пока предыдущий не завершён.
- Пропущенные периоды не накапливаются в очереди: после медленного вычисления следующий цикл планируется от текущего времени.
- Ошибка одной стратегии переводит в ERROR только её; общий scheduler продолжает обслуживать остальные.
- Остановка ожидает текущую задачу с ограниченным timeout; close останавливает стратегии, scheduler и пул.
- Сохранён ручной режим background=False и детерминированный tick_once для тестов.
- FBD-граф вычисляется детерминированной топологической сортировкой Кана с кучей готовых узлов вместо повторного сканирования всего pending-набора.

## Границы безопасности

- FBD по-прежнему не выполняет физические записи в драйверы.
- POINT_INPUT допускает к вычислению только GOOD-качество.
- Пул ограничивает число одновременно вычисляемых стратегий; это не является заявлением о производительности на 100k точек.
- Если один пользовательский блок зависает внутри вычисления, Python-поток нельзя безопасно принудительно завершить. Таймаут остановки переводит стратегию в ERROR; драйверные команды не затрагиваются.

## Тестирование

Добавлены проверки общего количества потоков, ограниченного пула, отсутствия параллельных циклов одной стратегии, изоляции отказа и вычисления графа из 1000 блоков. Результаты CI будут внесены после завершения Windows и Linux матрицы.
