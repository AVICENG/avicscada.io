# AVIC Core 1.0 — журнал сборки DEV198

## Цель цикла
Подключить Scheduler к общей модели лицензирования активных точек, продолжив единый учёт после FBD и Graphics.

## Сделано
- ScheduleService получил зависимость point_usage_service.
- Привязка точки к расписанию регистрируется под стабильным ключом schedule:<schedule_id>.
- Перед сохранением привязки проверяется лимит лицензии.
- При отвязке обновляется набор использования; общий сервис сохраняет слот, если точка всё ещё используется FBD, Graphics или другой функцией.
- CoreApplication передаёт Scheduler общий CoreObjectService.
- Добавлены тесты на bind/unbind и отказ по исчерпанному лимиту.
- Добавлена русская документация docs/SCHEDULER_POINT_LICENSING_DEV198_RU.md.

## Тестирование
- Новые тесты добавлены, но локальный Python/Windows запуск в этой среде не выполнялся.
- GitHub Actions для предыдущего коммита на момент начала цикла находился в состоянии pending.
- Новый CI после изменений должен подтвердить интеграцию. До этого статус — ожидает проверки, не PASS.

## Известные ограничения
- Объектный репозиторий и Scheduler используют разные SQLite-базы; межбазовая операция не является общей ACID-транзакцией. При ошибке записи Scheduler выполняется компенсация, а при сбое после отвязки может временно сохраниться лишняя активная ссылка. Требуется reconcile-процедура.
- Alarm и Historian пока не подключены к usage на уровне конфигурации. Нельзя считать их интегрированными только по факту записи alarm/history samples.
- Не проверены Windows acceptance, полный регресс FBD/Graphics/Scheduler и поведение с реальной подписанной лицензией на целевой машине.

## Готовность
DEV198 — функциональная интеграция Scheduler point bindings в общий лицензионный учёт; статус до CI: не подтверждён.
