# AVIC Field Runtime — граница отказоустойчивости (DEV177)

## Цель

Полевое управление не должно зависеть от жизненного цикла инженерного клиента или надзорного процесса. Полевое исполнение — отдельная подсистема, а не фоновый поток внутри Web/API Core.

## Целевая архитектура

1. Engineering Workbench — редактор и клиент. Закрытие окна не отправляет Stop в Runtime.
2. Supervisor / Platform Manager — конфигурация, лицензии, станции, мониторинг, резервирование, журналирование и управление жизненным циклом. Его перезапуск не должен останавливать Field Runtime.
3. Field Runtime — отдельный ОС-процесс/служба на полевом узле или контроллере. Он владеет расписанием FBD, локальными блокировками, watchdog, качеством данных и автономными алгоритмами.

## Правила управления процессами

- Save, Publish, Stop, Start, Restart и Kill — разные команды с разными полномочиями и аудитом.
- Обычная остановка Supervisor не имеет права посылать Field Runtime команду Stop.
- Остановка Field Runtime — отдельная операция обслуживания, запрещённая при отсутствии подтверждённого безопасного режима/резервного управления.
- Потеря связи с Supervisor не останавливает локальное выполнение.
- Команды управления должны иметь ID, generation/epoch, срок действия, защиту от повтора и проверку актуальности. Просроченная команда после восстановления сети отклоняется.
- Watchdog перезапускает отказавший процесс с ограничением числа повторов и переводом в FAILED/maintenance при цикле отказов.
- После восстановления связи требуется сверка версии опубликованной стратегии, состояния, качества входов и разрешений; удалённое управление возвращается контролируемо.
- «Оставить последнее значение выхода» не считается универсальным безопасным действием. Безопасность задаётся локальными interlocks, fail-safe состояниями и аппаратными защитами.

## Что выявлено в DEV175

CoreApplication создаёт FBDExecutionService внутри того же процесса. CoreApplication.close() ранее останавливал FBD scheduler, затем драйверы и station runtime. Это означало, что остановка Core прекращала AVIC FBD execution, если стратегия работала в этом процессе.

## Реализация DEV177 — защитный промежуточный этап

- CoreApplication.close() теперь выполняет preflight активных FBD-стратегий.
- Если есть RUNNING/STARTING/STOPPING стратегия или in-flight worker, закрытие Core блокируется до любых остановочных действий над FBD, драйверами и станциями.
- Событие и audit-запись фиксируют блокировку и список стратегий.
- После подтверждённой остановки стратегий повторный вызов close() может завершить Core shutdown.
- Это намеренная временная блокировка, а не окончательная автономность.

## Критическое ограничение

DEV177 не создаёт отдельный Field Runtime процесс. Пока FBDExecutionService находится в процессе Core, принудительное завершение процесса ОС, отключение питания или авария хоста всё ещё прекратит выполнение AVIC FBD в этом процессе. Предохранитель защищает от штатной команды закрытия, но не от kill/crash/power loss. Нельзя считать полевое управление автономным до реализации и проверки отдельной службы исполнения.

## Следующий этап

1. Выделить Field Runtime как отдельный пакет и исполняемую службу с собственным владельцем данных.
2. Ввести аутентифицированный локальный IPC и протокол команд с epoch/TTL/idempotency.
3. Перенести владение FBD scheduler и опубликованными runtime-стратегиями из Core в Field Runtime.
4. Реализовать платформенный watchdog, autostart и bounded restart policy.
5. Проверить crash Supervisor, закрытие Workbench, потерю Ethernet/BACnet, reboot хоста и восстановление связи.
6. Отдельно испытать failover/резервный узел и процедуру безопасного обслуживания.

## Приёмочные критерии

- Закрытие Workbench не меняет RUNNING состояние стратегии и её tick counter.
- Принудительное завершение Supervisor не прекращает tick counter Field Runtime.
- Отключение связи с Supervisor не прекращает локальные циклы и расписания.
- Устаревшие команды после восстановления связи отвергаются.
- Потеря полевого контроллера приводит к документированному безопасному поведению оборудования, а не к обещанию продолжения исполнения.
- Ни один тест без физического контроллера не считается подтверждением аппаратной безопасности.
