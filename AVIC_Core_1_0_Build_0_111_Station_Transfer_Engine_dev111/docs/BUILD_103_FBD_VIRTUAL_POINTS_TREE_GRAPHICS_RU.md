# AVIC Core 1.0 — DEV103

## Цель сборки
Сделать сквозную связь между инженерным деревом, FBD Runtime, виртуальными FBD-точками и редактором мнемосхем. DEV103 продолжает DEV102 и не заменяет физические точки виртуальными.

## Реализовано

1. **Виртуальные FBD-точки Core (`FBDExposedPoint`).** При компиляции FBD Studio проект регистрирует выходы с постоянными ID как отдельные Core-объекты. Они принадлежат станции и исходному FBD-документу, имеют тип, единицу, provenance и read-only направление. Физический Device для них не создаётся.
2. **Общий Point Runtime.** `read`, `snapshot`, `subscribe` и общий `/api/points/{id}/runtime` поддерживают физические и виртуальные FBD-точки. Драйвер не может публиковать значения в виртуальные FBD-точки.
3. **Циклическая публикация FBD.** `FBDExecutionService` связывает исходный Studio module ID с скомпилированным Core FBD-узлом и публикует его `OUT` в соответствующую виртуальную точку после успешного цикла. Публикация значения в Core Runtime не является записью в контроллер.
4. **Качество сигнала.** До первого цикла качество `UNCERTAIN`; успешный цикл публикует `GOOD`; остановка стратегии переводит виртуальные точки в `STALE`; ошибка расчёта — в `BAD_CONFIGURATION`.
5. **Управление runtime API.** Добавлены локальные маршруты `/api/fbd-runtime/{id}/start`, `/stop`, `/status`, `/tick`; для детерминированной приёмки `start` поддерживает `background: false`, по умолчанию используется фоновый цикл. `tick` допускает только переопределения виртуальных `BOOL_INPUT`/`FLOAT_INPUT` в тестовом цикле; это не команда оборудованию.
6. **Инженерное дерево и Point Manager.** Физические и FBD-точки показывают value/unit/quality/timestamp. В открытом дереве значения обновляются каждые 2 секунды.
7. **Graphics.** Каталог точек Graphics включает виртуальные FBD-точки. Сохранение привязки допускает Core `Point` и `FBDExposedPoint` только своей станции. Перетаскивание физической или FBD-точки из общего дерева на символ мнемосхемы создаёт binding по стабильному Core ID. Для вентилятора по умолчанию назначается feedback/status animation, для прочих символов — value.

## Сквозной проверенный сценарий

- Создать FBD Studio graph с BOOL_INPUT → AND → exposed OUT.
- Скомпилировать граф в Core FBD.
- Проверить регистрацию FBDExposedPoint в Point Runtime с `UNCERTAIN`.
- Запустить Core FBD Runtime и выполнить цикл: значение виртуальной точки становится `True`, quality `GOOD`.
- Передать `False` во входной BOOL_INPUT тестового цикла: выходная FBD-точка становится `False`, quality остаётся `GOOD`.
- Убедиться, что точка доступна через `/api/engineering/points`, Engineering Tree и Graphics Point Catalog.
- Сохранить привязку виртуальной точки к графическому вентилятору и оценить binding через Graphics Runtime.
- Остановить стратегию: качество виртуальной точки становится `STALE`.

## Ограничения и незавершённые работы

- В DEV103 не реализована публикация Graphics Page в отдельный операторский read-only URL/workspace.
- Не подключён Command Manager к реальным BACnet/Modbus write services. Переключение входа через `/tick` — только проверка FBD Runtime/виртуальной точки; оно не включает физический вентилятор.
- `BOOL_OUTPUT`/`FLOAT_OUTPUT` в текущем компиляторе остаются наблюдаемыми выходными узлами стратегии; физическая команда не выполняется.
- Нужны lifecycle-проверки FBD-точек при удалении/перепубликации исходных модулей и документов (orphan/revocation).
- Требуется полноценная проверка RBAC/станционных scope для runtime и publish endpoints, а также Windows acceptance.
- Многопортовые выходы и межстраничные Connective остаются за пределами текущего компилятора.

## Принцип безопасности
FBD virtual point — read-only программный сигнал. Graphics binding — отображение/индикация. Ни один из новых маршрутов не посылает команду в BACnet/Modbus и не меняет конфигурацию сетевого адаптера.

## Приёмка Windows
Инструкции и список команд для Windows находятся в `INSTALL_DEV103_RU.txt`. Перед подключением физического оборудования требуется отдельная приёмка Command Manager, RBAC, field-write policy и драйверного подтверждения обратной связи.
