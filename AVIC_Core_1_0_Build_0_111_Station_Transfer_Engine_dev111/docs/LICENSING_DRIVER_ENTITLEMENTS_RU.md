# Лицензионная проверка Core и Driver Manager

## Что реализовано в этом изменении

- `CoreApplication` принимает пару `license_service` + `license_file` и передаёт её в `CoreObjectService`. Проверка лимита уникальных объектов `Point` выполняется внутри транзакции сохранения графа; обновление существующего UUID не расходует дополнительный слот.
- `InstallationLicenseService.assert_feature_enabled()` проверяет действительность подписи/срока/Host ID (через `inspect`) и точное совпадение ключа функции с подписанным списком `features`.
- `DriverManagerService.catalog()` публикует `license_feature` для каждого драйвера.
- Создание экземпляра, изменение конфигурации остановленного драйвера и запуск требуют соответствующего entitlement, если лицензионный сервис подключён. Остановка и диагностика остаются доступными для безопасного вывода из эксплуатации.
- Уже работающая сессия при повторном вызове `start_instance()` возвращает текущую диагностику до повторной проверки entitlement: изменение статуса лицензии не останавливает уже работающий процесс автоматически.

## Ключи функций

Ключи сравниваются точно, без неявного преобразования. Например: `driver.bacnet-ip`, `driver.modbus-tcp`, `driver.knxnet-ip`. Подписанный файл лицензии должен содержать именно эти строки в `features`.

## Подключение

Создайте `LicenseManager` с публичным Ed25519-ключом AVIC, затем `InstallationLicenseService(data_dir, manager)`. Передайте оба объекта в композиционный корень:

```python
core = CoreApplication(
    data_dir,
    license_service=installation_license_service,
    license_file=path_to_signed_license,
)
```

Передача только одного из двух параметров является ошибкой конфигурации.

Для Workbench доступны переменные окружения `AVIC_LICENSE_PUBLIC_KEY` (путь к публичному PEM Ed25519 ключу AVIC) и `AVIC_LICENSE_FILE` (путь к подписанному `.aviclic`). Нужно задать обе переменные. Если задана только одна, запуск Workbench завершается с явной ошибкой, а не молча отключает лицензионную проверку. Приватный ключ выпуска лицензий в установку не включается.

## Ограничение текущего этапа

Если `license_service` не передан, Core остаётся в режиме разработки/совместимости и лицензионные entitlement-проверки драйверов не выполняются. Это не следует считать готовым коммерческим режимом. Подключение конфигурации публичного ключа и файла лицензии к установщику/Workbench, отзыв/перевыпуск лицензий, перенос Host ID, UI статуса/остатка точек и сквозная авторизация всех API остаются отдельными задачами. Закрытый ключ выпуска лицензий не должен попадать в клиентскую поставку.

## Проверки

Добавлены тесты на передачу сервиса через `CoreApplication`, лимит точек в штатном пути, точные ключи возможностей драйверов и отказ создания/запуска при отсутствии entitlement. Результаты выполнения тестов фиксируются после CI для этого коммита.

## API статуса лицензии для Workbench

- `GET /api/licensing/status` возвращает configured/valid/reason, имя заказчика, ID лицензии, Host ID, лимит, число активных лицензируемых точек, остаток и список feature keys.
- `GET /api/licensing/point-usage` возвращает счётчики типов точек и теперь учитывает лимит из подписанной лицензии, если лицензия подключена.
- API не возвращает путь к файлу лицензии, PEM-ключ или приватные данные подписи.
- В незапущенном коммерческом режиме API явно возвращает `configured=false`, `valid=null`, `LICENSE_NOT_CONFIGURED`, а не изображает наличие лицензии.
