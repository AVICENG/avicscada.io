# AVIC Deployment Manager — DEV110

## Назначение

`.avicpkg` переносит инженерную конфигурацию проекта со станции разработки на целевую установку AVIC. Реализация DEV110 — первый проверяемый слой переносимого пакета, проверки целостности/совместимости и безопасного staged import. Это не следует путать с полным промышленным rollout.

## Состав пакета

- Относительные файлы проекта: FBD, графика, страницы, конфигурация и другие файлы, находящиеся в переданном `source_root`.
- `avic-package.json`: формат, версия, проект, исходная версия Core, требуемые модули, инвентарь файлов, размеры и SHA-256.
- Site Profile и секреты не включаются в `.avicpkg`.

Экспорт исключает файлы с именами/путями, распознаваемыми как `.env`, secrets, credentials, private keys, `.pem`, `.p12`, `.pfx`, `.key`. Символические ссылки запрещены. Передаваемый `source_root` должен быть именно каталогом переносимой конфигурации проекта, а не произвольным каталогом всей ОС или пользовательского профиля.

## Рабочий процесс

1. На инженерном компьютере вызвать `DeploymentManager.export_project(...)`.
2. На целевой установке вызвать `inspect_package(...)`; проверить Core version и наличие required modules. Пока нет утверждённой матрицы миграций, различие версий Core блокирует импорт.
3. Сформировать Site Profile для конкретного объекта отдельно. В DEV110 допускаются только обычные параметры с безопасными ключами; секреты должны поступать в целевой SecretStore, а не в профиль/пакет.
4. Вызвать `stage_import(...)` с `expected_package_id`, полученным при preview.
5. Проверить развернутые файлы и Site Profile. Импорт создаёт состояние `STAGED_NOT_ACTIVATED`; активная папка не перезаписывается.

## Ограничения DEV110

- Пока нет UI Deployment Manager и HTTP upload/download workflow. Сервис доступен как Core API Python.
- Нет автоматического извлечения конфигурации из всех внутренних SQLite БД AVIC; переносится содержимое явно заданного каталога проекта.
- Нет автоматической миграции между версиями Core: несовпадение версии блокирует импорт.
- Нет криптографической подписи издателя. SHA-256 проверяет целостность относительно манифеста, но сам по себе не подтверждает издателя/подлинность.
- Нет автоматического сопоставления BACnet/Modbus устройств, проверки связи, запуска драйверов или реального управления.
- Нет атомарной активации/rollback работающей станции и нет записи deployment history в UI. Staged import не запускает оборудование.
- Политика исключения секретов по именам — дополнительная защита, но не замена SecretStore и ручного контроля состава источника.

## Безопасность

Импорт проверяет дубли путей, traversal, symlink, список файлов, размер, хеши, ограничения распаковки и повторное изменение пакета после preview. Непустой целевой каталог запрещён. Site Profile не принимает ключи, похожие на пароли/секреты/токены/credentials.

## Пример

```python
from avic_core.deployment import DeploymentManager

manager = DeploymentManager()
package = manager.export_project(
    r"C:\AVIC\Projects\AHU-01", r"C:\Export\AHU-01.avicpkg",
    project_id="project-ahu-01", project_name="AHU-01",
    source_core_version="1.0.0.dev110", required_modules=["bacnet", "graphics"],
)
preview = manager.inspect_package(package, target_core_version="1.0.0.dev110",
                                   installed_modules=["bacnet", "graphics"])
# На целевом узле: сохранить preview.package_id и после проверки вызвать stage_import.
```
