# DEV224 — пакетный опрос Modbus TCP

Дата: 27.11.2026  
Статус: **реализация внесена; автоматическая проверка GitHub Actions ожидает выполнения**.

## Что изменено

- В общий адаптер Rust/C добавлен планировщик пакетного чтения Modbus.
- Bindings сортируются по Function Code и адресу.
- Смежные и перекрывающиеся диапазоны объединяются в один запрос, если у них одинаковый Function Code.
- Разрывы адресов не объединяются: драйвер не читает незаданные регистры «на всякий случай».
- Соблюдаются пределы протокола: FC01/FC02 — 2 000 бит; FC03/FC04 — 125 регистров на запрос.
- Диапазон разбивается на несколько запросов, если объединённая длина превысит лимит.
- Ответ диапазона проверяется по длине и типу значений, затем нарезается на индивидуальные bindings.
- Для каждой точки отдельно выполняются decode data type, byte order, word order, scale и offset.
- Ошибка чтения одного диапазона переводит в ошибку только точки этого диапазона; другие диапазоны продолжают опрашиваться.
- В диагностику добавлены поля modbus_batch_requests и modbus_batches_last_poll.

## Регрессионные тесты

Добавлен файл tests/test_modbus_batch_planner_dev224.py:
- объединение смежных регистров;
- отсутствие объединения разных FC и адресных разрывов;
- разбиение на границе 125 регистров;
- отказ от недопустимого диапазона и многобитного point binding для FC01/FC02;
- подтверждение, что три смежные точки обслуживаются одним transport read и корректно декодируются.

## Техническая основа лимитов

Официальная документация libmodbus указывает максимум 125 регистров для modbus_read_registers; API ограничивает чтение битов 2 000 значениями. Эти лимиты применяются планировщиком до отправки запроса.
