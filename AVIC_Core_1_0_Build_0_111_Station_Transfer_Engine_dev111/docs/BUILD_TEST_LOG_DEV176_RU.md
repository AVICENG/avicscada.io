# DEV176 — Глобальная идентичность блоков FBD Studio

Дата: 2026-11-26
Ветка: `dev113-network-drivers`
Базовый HEAD: `8758e7a528941540a231a9e9b72929d25cb9cf53`

## Основание

Сверка с компонентной моделью Niagara выявила несоответствие: идентификаторы компонентов должны однозначно разрешаться в контексте всей станции/стратегии. В AVIC FBD Studio серверная проверка ранее обеспечивала уникальность ID блока только внутри отдельной страницы, тогда как компилятор строит общую таблицу модулей по ID для всего многостраничного проекта.

Это создавало риск перезаписи одного блока другим при совпадении ID на разных страницах. Интерфейс обычно создаёт UUID, но сервер не должен полагаться на корректность клиента.

## Изменение

- Добавлена серверная проверка уникальности module ID по всему FBD Studio документу.
- Сохранена локальная проверка дубликатов на странице; глобальная проверка выполняется дополнительно.
- Добавлен регрессионный тест: два разных листа с одинаковым module ID должны отклоняться API с HTTP 400.
- Версия пакета изменена на `1.0.0.dev176`.

## Границы

Это исправление не реализует межстраничную компиляцию Connective, не меняет формат существующих корректных проектов и не меняет Core FBD Runtime. Документы с глобально уникальными ID сохраняют прежнее поведение.

## Проверка и статус

Тест добавлен, но фактический запуск pytest, Windows acceptance и CI для этого изменения ещё не выполнены. Предыдущие GitHub Actions на базовом HEAD завершались ошибкой до публикации шагов; причина не установлена. DEV176 не объявляется принятым до успешного CI и локальной проверки на Windows.

## Следующие проверки

1. Прогнать весь набор FBD Studio persistence/compiler tests.
2. Проверить существующие проекты на повторяющиеся module ID между страницами до их компиляции.
3. Добавить серверную проверку структуры локальных links и references.
4. После валидатора реализовать разрешение Connective в единый граф с сохранением типа и качества сигнала.
